# Business rules 30–84 — the invariants

The filename keeps its original range: it is a stable citation key linked from code and the other skills. Each entry is the CONTRACT layer of a rule — what must hold today, the functions and columns that hold it, the rules it leans on — in about 150 words, ending with a pointer into the narrative file that records the incident, the reasoning and the dated history (verbatim, including the long-form invariant each rule carried here until 2026-09-22). Rule numbers are a stable citation key — never renumber; retire a rule in place and give a new one the next free number (`npm run rules:next`).

30. **Confirmation is the configured cadence's job; ICMP only fills in the loss ratio** — `monitorStatus` reaches `down` when N missed polls are OUTSTANDING against the operator's configured transport at their configured `intervalSeconds`. **The counter is a LEAKY BUCKET WITH A CEILING** (`utils/monitorStatus.ts` → `nextFailureBucket` + `monitorStatusFor`, which the probe path CALLS): a miss adds one to `consecutiveFailures`, an answered poll takes one back (floored at 0), and the level LOCKS at `bucketCapFor(N, recoveryPolls)` the moment a miss carries it to N. The verdict: `cf == 0` is `up`, an ANSWERED probe is `recovering` whatever the level, a MISS is `down` at or above N and `warning` below it. Recovery costs exactly the cap however long the outage ran; `consecutiveSuccesses` decides nothing (`polaris-domain-model` → dormant-columns.md). **N is the covering automation's `missedPolls`** (rule 36), never a Monitor Settings value; the CADENCE still comes from the monitor-settings hierarchy, and `resolveProbeIntervalSec` applies exactly one clamp (parent dark ⇒ 2× interval). **A probe may decline to be a reading**: `ProbeResult.skipped` (the vCenter probe when vCenter is unreachable; `responseTimePolling === "disabled"`, gated by the shared `responseTimeProbeShouldQueue` in both publishers) writes no sample and moves no counter, bumping `lastMonitorAt` alone; a re-queued duplicate job records nothing (`probeStillDue`). **The ICMP loss sweep never calls `recordProbeResult`** — it runs uniformly over every eligible asset every cycle through `utils/burstPing.ts`, and `probeKind` keeps its rows out of every response-time reader and rollup (only `probeLossQuery` and the email loss chart read all kinds). → [narrative-25-35.md#rule-30](narrative-25-35.md#rule-30)

31. **The login page is the way back in, so restricting it is opt-in and must refuse to lock you out** — `loginAccessConfig` (default **off**) restricts local login by source IP via `utils/ipScope.ts`, gating **both halves or neither**: `/login.html` (socket destroyed, stealth posture) AND `POST /auth/login` + `/auth/login/totp` (the same generic 401 a wrong password gets, plus `auth.login.blocked_source`). LDAP shares the login route and is gated; **SSO is never gated**, and a RATE LIMITER counts as a gate — `/auth/azure/login` carries its own `ssoEntryLimiter`, and **an SSO entry ceiling must never sit below the callback ceiling behind it**. It **fails open** on a settings read error; the PUT refuses a scope excluding the caller's own `req.ip`, which the GET returns as `callerIp`. Pinned by `tests/unit/loginAccessService.test.ts` and `tests/integration/loginAccessGate.test.ts`. → [narrative-25-35.md#rule-31](narrative-25-35.md#rule-31)

32. **A reset condition answers "what has to become true again", so it starts as the trigger inverted — and it resolves where the alert lives** — custom-condition mode is offered on every continuous trigger (`TRIGGER_TYPES_WITH_RESET_CONDITIONS`; `event` / `change` refused), pre-seeded with `invertedLeaf` / `invertedTree` (De Morgan, and/or-only). (a) While firing, **the tree is the sole recovery authority**, evaluated in its own post-loop pass over rows re-read from the DB. (b) Resolution is **dimension-first**; the per-asset fallback is reserved for a leaf in ANOTHER dimension space (`dimensionSpaceOf`), a leaf with no reading for the firing component says nothing, and reset leaves inherit the trigger's port coverage (`coverUnpinnedPoe`, rule 57). (c) Kind coherence is enforced on single triggers too. (d) Reset leaves inherit the trigger's measurement window. (e) `event` / `change` get the **counterpart Event** instead (`TRIGGER_TYPES_WITH_RESET_EVENT`, prefilled from `RESET_EVENT_SUGGESTIONS`), scoped to the SAME subject; a signal writing one verb for both directions is split (`capacity.severity_recovered`, `platform.lifecycle_recovered`), and the trigger's own direction lives in `trigger.detailsMatch`, which the wizard renders and saves. `cooldownSec` is retired from the builder and dormant (`polaris-domain-model` → dormant-columns.md); the wizard writes null on every save. → [narrative-25-35.md#rule-32](narrative-25-35.md#rule-32)

33. **A device that answers is not a device that works — and the check that proves it belongs to the VENDOR, not to a login** — the HTTP check is a **manufacturer custom widget** (`ManufacturerCustomWidget.widgetType="http"`), not a polling method (retired 2026-08): a check varies by vendor AND model while a login varies by vendor, so sharing one row meant duplicating passwords. Decisions: the **body match is load-bearing** (a 200 whose body doesn't match FAILS; no lax toggle); **status is judged before content**; **redirects are never followed**; the body is **capped at 64 KB**; the credential is **authentication only, with no "none" mode**; **`authMode` is stated, not guessed** (Digest is a handshake — fire bare, read the challenge, re-fire **exactly once**); it writes `AssetStateSample` 0/1 **pass or fail** plus a success-only RTT gauge and **never moves `monitorStatus`**; and **`netGuard` deliberately does not apply**, the target being the monitored asset's own private address. → [narrative-25-35.md#rule-33](narrative-25-35.md#rule-33)

34. **An active scan finds things; a separate grant adds them** — a **Discovery** (`NetworkScan`) sweeps addresses the operator names, the only Polaris feature that touches hosts it has no prior relationship with. **Scanning and adopting are separate grants** (`networkScan` authors and runs, `assets:write` chains on adopt, and the wizard RENDERS the missing grant); it is **opt-in and IDS-visible**, with no scheduler and no shipped default range; **credential order is the try order** and the first method that answers wins; **adoption is new-addresses-only**; it is neither an integration type nor a `DiscoveryRun` row, and there is no `network-scan` AssetSource kind. A Discovery is **private or shared**: visibility decides who may see and RUN one, ownership who may edit it (`networkScan:fullwrite` reaches anyone's); an invisible row answers 404, `name` is unique per owner, existing rows were migrated public, new ones default private, and the export carries no visibility. → [narrative-25-35.md#rule-34](narrative-25-35.md#rule-34)

35. **The GAL is a mirror, not a source of truth — and Polaris only ever deletes what it wrote** — directory sync is opt-in per integration (`config.enableDirectorySync`, separate from `enableDirectorySearch`, which persists nothing) and runs as a post-sync pass of the owning integration's discovery run. (a) **Provenance decides deletion**: `DirectoryContactSource` records every (integration, directory object) the sync created; a `Contact` dies only when its LAST provenance row goes, a hand-added row has none, and adoption drops provenance. (b) **A Polaris `User` or a manual `Contact` on an address wins.** (c) **An empty or catastrophically-shrunken read never wipes** — the deletion half is skipped with a warning. (d) Synced entries AND the live GAL fan-out are gated on `automationManagement`, not `contacts:read`. (e) **No directory PII reaches `Event.details` or the logs** — counts only. → [narrative-25-35.md#rule-35](narrative-25-35.md#rule-35)

36. **The automation decides what "down" means; a device no automation covers is never judged** — a `monitorStatus == down` automation's **`missedPolls`** IS the definition of down for every device it covers (`downDetectionService.resolveDownThreshold`, once per probe) and is the trigger's ONLY timing number: the wizard states it in `Sustained for (polls)` and zeroes `forPolls` / `forDurationSec` on a bare down trigger. Precedence is rule 18's ladder; same-rank ties resolve to the **smaller count**, then older `createdAt`, then lower `id`. **A device covered by NO down automation reads `passive`**: polled, sampled, charted, no verdict; entering or leaving it is a configuration edge (`isConfigStatusEdge`), and anything testing `!== "up"` for "unreachable" must exempt it. A zero-rule fleet stamps `monitor.down_detection_absent` once. **The same automation owns the way back UP**: its reset hold in POLLS (`recoveryPollsFor`, from `reset.sustainPolls` or the `sustainSec` mirror divided by the cadence) sets the bucket cap of rule 30, so an outage owes exactly the operator's number of answers; `downRecoveryConsumesSustain` stops the engine charging the wait twice, and only `mode: "auto"` counts (a `condition` reset is its own authority, rule 32a). `failureThreshold` and `Asset.awaitingRecoveryConfirm` are dormant (`polaris-domain-model` → dormant-columns.md). **The automation also decides what colour Down is**: `down` is painted in the covering automation's severity on every chart through one palette in two files (`downSeverityHex` / `DOWN_SEV_COLOR`, pinned by `tests/unit/downSeverityColor.test.ts`); the Status pill does not move. The palette itself is `polaris-ui-canon` → canon-charts-widgets.md's. → [narrative-36-43.md#rule-36](narrative-36-43.md#rule-36)

37. **An automation only fires about a device Polaris is actually polling** — ONE gate, `assetCanTrigger` in `notificationEngine`: the asset must be `monitored` AND not suppressed (maintenance window or dependency-suppressed), applied by EVERY trigger path, event and change included. The monitored half is pushed into SQL for the threshold, composite and preview loads (`scopeWhere(scope, monitoredOnly)`) and checked per row in the event tail. Rule 10's four unmonitorable statuses fold in through `monitored`. Un-monitoring a device **clears** its live alerts through `clearVanishedStates` (`notification.out_of_scope`), because `monitorStatus` is NOT cleared when monitoring stops. A **null `assetDetail` still fires** (`asset.deleted` must not be swallowed), as do system-scoped events. The raw scope resolver stays for surfaces asking a different question (the device-list preview, the dimension picker, mass pinning, `Contact.assetCondition`). Division of labour: rule 16 says what a maintenance window does to the asset, this rule is the gate that reads it, rule 78 is the one opt-out from the suppression half, and rule 80a adds the event-time gate beside this one. → [narrative-36-43.md#rule-37](narrative-36-43.md#rule-37)

38. **A device behind a dark parent is not accused, and it is not released on one packet** — (a) **Release is asymmetric.** Entering suppression needs every effective parent confirmed `down`; LEAVING it needs the parent genuinely BACK. The release side is a WHITELIST, `RELEASES_SUPPRESSION` = `up`, `unknown`, `passive` (neither of the last two is a claim about reachability), so `down`, `recovering` AND `warning` all hold. The child's persisted `dependencySuppressed` selects the side (`SuppressionAssetState.currentlySuppressed`); release cascades one layer per pass. (b) **A miss the upstream explains is GREY, not red.** A suppressed asset is still probed at half cadence; `recordProbeResult` stamps `AssetMonitorSample.dependencyDown` from the asset row's own flag (never re-derived — the reconciler owns it), the rollups carry `dependencyFailureCount`, and `probeOutageService` hands every chart an `OutageKind`. A run splits at a change of kind, a rollup bucket must qualify WHOLE (`dependencyFailureCount >= failureCount`; NULL reads red), and it is deliberately NOT a band — that vocabulary is maintenance's (rule 16). → [narrative-36-43.md#rule-38](narrative-36-43.md#rule-38)

39. **How a person wants to be reached is theirs, not the automation's — but an automation offering one way still reaches them** — `User.notificationPreference` (`email` default | `push` | `any`) is an ACCOUNT setting: every client reconciles ITS OWN subscription to it at boot (`polarisPush.syncToPreference`) without prompting, and a browser at permission `default` is **asked once** (`polarisPush.shouldOfferEnrollment`, recorded in `localStorage` when the offer is SHOWN; never on iOS outside the installed app). The preference saves even when the browser refuses. A notify action is **plural**: `channelIds` behind one recipient list, `channelId` as the primary mirror (`notifyChannelIds` the only reader; `assertActionRefs` refuses disagreement), expanded by `actionsToTargets` to one DeliveryTarget per channel. `respectUserPreference` filters ACCOUNTS only (a typed address or contact expressed no preference — unknown means deliver, rule 25), and only when the action group offers BOTH methods (`actionsCarryBothMethods` / `hostOffersBothMethods`). **A preference never deletes an alert**: `preferenceWithholds` keeps a recipient on the other channel when the chosen one cannot reach them, and `enqueuePushFallbacks` re-routes a dead endpoint (410) to the action's own email channel once. An unrecognized preference normalizes to `email`; the two broadcast toggles stay push-only. Changes write `user.notification_preference.changed`. → [narrative-36-43.md#rule-39](narrative-36-43.md#rule-39)

40. **Two assets on one address is a conflict; one asset on a stale address is not** — `Asset.ipAddress` carries no uniqueness constraint (unlike rule 3's per-subnet index), so the duplicate is found by the `detectDuplicateIpAssets` sweep (10m) and reported as the `duplicate-ip` Conflict + a `conflict.detected` Event. (a) **Only network-present assets count** (status not in `UNMONITORABLE_STATUSES`). (b) **A claim counts only while CURRENT**: operator-owned (`ipOverride` equals the address, or `ipSource="manual"`) never expires; a discovered one needs its `(asset, ip)` `AssetIpHistory` row within `CLAIM_FRESH_DAYS` (7). (c) **Two DEVICES, not two rows** — members sharing a non-null MAC are a merge's problem. (d) **One pending row per ADDRESS** (`proposedAssetFields.members[]`; `assetId` is the lowest member). (e) **Accept is refused**; the verbs are `POST /conflicts/:id/reassign-ip` (refuses an address another present asset holds) and `POST /conflicts/:id/merge` (through `assetMergeService.mergeAssets`, `Conflict.assetId` re-pointed first); reject dismisses that member set. (f) **A resolved collision closes itself** (`rejected` by `system:auto-resolved`). A group qualifies by ANY of: (g) a claimant in `CONFLICT_ELIGIBLE_ASSET_TYPES` (`switch` / `access_point` / `firewall` / `server`); (h) claimants with disjoint `AssetSource.sourceKind` sets AND a deliberate address (`vipInfo`, `dhcpBinding="reservation"`, or `DELIBERATE_RESERVATION_SOURCE_TYPES` — three columns because rule 23 makes them three facts); (i) an operator-owned claim (`claimIsOperatorOwned`). `qualifiedBy` records which. **Write time triggers it too**: `POST /assets` and an IP-changing `PUT /assets/:id` run `reconcileDuplicateIpForAddresses` scoped to the touched addresses and return the card as `ipConflict`; `GET /assets/ip-check` simulates the incoming claim through the same `groupCurrentClaims`. Imports are not triggers. **Merging takes `assets:fullwrite`**; reassign stays `write`. → [narrative-36-43.md#rule-40](narrative-36-43.md#rule-40)

41. **A subnet dies with its FortiGate, and the chassis — not the name — says which gate that is** — a discovered `Subnet` records `fortigateSerial` beside `fortigateDevice`, because a name cannot tell a RENAME from a REPLACEMENT. `utils/chassisIdentity.ts` → `classifyChassis` is **tri-state in both directions**: a NULL stored serial learns on first sight, an unreadable serial THIS run applies no constraint, and the comparison is against a SET per device (the gate's own serial plus every `ha_slave[]`). Anything outside it raises the **additive** `chassis-replaced` Conflict (`subnetChassisConflictService`): subnet and reservations copied to the archive, nothing released or re-pointed while pending, dedup on the (old, new) serial pair. **Discovery retires a dead row itself**: Phase 1's create path archives a deprecated row when a DIFFERENT gate re-reports its exact CIDR (`classifyDeprecatedSupersede`, `deprecatedByBlockCidr`); a same-gate or ambiguous match is KEPT, and the rule 42 exclusion check runs first. **A retired subnet MOVES to `ArchivedSubnet` / `ArchivedReservation`** rather than going `deprecated`, which frees the `(blockId, cidr)` index and locks the retired rows by construction; archiving is exempt from rule 4. Rule 23 is unchanged. Phase 1 must mirror a re-pointed `fortigateDevice` onto the in-memory row Phase 2 filters. → [narrative-36-43.md#rule-41](narrative-36-43.md#rule-41)

42. **Some address space is not one network, and the way to say so is to exclude it** — a `SubnetExclusion` is a CIDR the operator declared out of scope for the networks list (IPAM → Networks → **Exclusions**), for address space that is the SAME at every site and would otherwise raise a `chassis-replaced` card (rule 41) every run. **Global, not per block.** **`cidr` is the IDENTITY**: normalized on write, FROZEN after create (the PUT and its Zod schema take `name` / `notes` only). **Containment is ONE-directional** — an exclusion covers itself and anything narrower, never a wider discovered CIDR — and the MOST SPECIFIC match is reported. **One enforcement seam for creation**, `createSubnetRowChecked` (`opts.exclusions` lets discovery load the set once per run); **the allocators treat excluded ranges as taken space, never a refusal**, and `previewBulkAllocate` builds the same list. **Discovery skips a covered scope WHOLE** in Phase 1, above the existing-row branch, and exempts it from the Phase 2 stale sweep. **Adding an exclusion destroys NOTHING** (`matchCount` / `matches` reported). IPv4-only. Reads `subnets:read`, mutations `subnets:fullwrite`. → [narrative-36-43.md#rule-42](narrative-36-43.md#rule-42)

43. **A grant is only as narrow as the act it names** — (a) **Deploying the Polaris Agent is `assets=fullwrite`** (install / retry / reinstall / upgrade / uninstall, `POST /assets/bulk-agent-install`); enabling a class block's `agentDeploy.enabled` CHAINS the same grant onto `integrations=write` (`assertAgentDeployGrant`), on the ON transition only; the client withholds the verbs through `canDeployAgent()`. (b) **`assetsProbe` is read-only** (`none | read`); the dependency-test outage simulation moved to `assetMonitorSettings=fullwrite`. (c) **`credentials` carries the ownership dimension**: `write` creates and reaches own rows, `fullwrite` reaches any, `POST /credentials/test` naming a stored `id` included; an unowned row is fullwrite-only. Ladders are clamped by `normalizePermissions`, `permissionOf` and `requirePermission`. (d) **A rung exists only where it grants something the rung below does not** (migration `20260922000000_rbac_catalogue_hygiene`; `processControl` removed; `fullwrite` survives only on an ownership key or a named act, pinned by `tests/unit/permissionLevelLadders.test.ts` → "no dead top rung"). Downloading a backup is `serverSettingsData=write` (a `none | write` ladder); the auto-decommission thresholds ride `assetMonitorSettings`. **`readonly` is the FLOOR for every built-in role**, except `user` holding `networkScan=none`. (e) **The gap (d) recorded is closed** (migration `20260923000000_authentication_function_key`): the four identity providers' settings and test routes, the passkey policy and the password policy moved to a new **`authentication`** key (`none | read | write`), so `serverSettingsSystem` now tops out at `write`; seeding is DERIVED from each role's old System level (`fullwrite`→`write`, `read`→`read`, `write`→`read` — the one tightening) and MUST precede the fold, or every admin-equivalent role reads as a plain `write` holder. Group mappings stay on `users=fullwrite`; the login-page source-IP restriction stays on `serverSettingsSystem`. (f) **One act on two keys is the same defect inverted** (migration `20260923010000_fold_manufacturer_aliases`): `manufacturerAliases` is FOLDED into `manufacturerProfiles` (catalogue 33 → 32), because an alias rewrites `Asset.manufacturer` fleet-wide and that value selects the device's profile; the routes keep `/api/v1/manufacturer-aliases`; seeding takes the LOWER of the two stored levels; the migration's `pg_temp.perm_rank` MUST be `CREATE OR REPLACE` because `prisma migrate deploy` runs every pending migration in one session. Pinned by `tests/unit/manufacturerAliasesFoldLockstep.test.ts`. Rule 48 is the promotion guard beside this. → [narrative-36-43.md#rule-43](narrative-36-43.md#rule-43)

44. **A quiet window withholds the reminder, not the alert — and the reminder that follows says how long** — `repeat.quiet` is a list of up to 8 recurring windows (`utils/quietTime.ts`) in the recurrence shape maintenance uses (`polaris-domain-model` → alerting.md § Recurrence shape; server-local wall clock, so a 22:00–06:00 window survives DST), edited with the shared `PolarisRecurrence` editor. (a) **Held, never skipped**: `repeat.lastSentAt` is not advanced on a withheld reminder, so it goes out on the first tick after the window. (b) **The reminder that ends a hold reports it**: `escalationState.quietHeldSince` / `quietHeldCount` put `{repeat.quiet}` in the body and `· ACTIVE 9h 12m` in the `[REMINDER n]` subject (only when no operator subject template is set). (c) **The hold is closed by the SEND**, not by the window ending. (d) **A hold exists only where a reminder was actually withheld.** (e) **A malformed quiet blob must not silence reminders**: `normalizeRuleToV2` re-parses with `quiet` stripped. Quiet time touches neither the first alert, the escalation tiers nor the reset notifications; `stopAfterHours` is wall time from the fire; the maintenance / suppression pause is NOT a quiet hold (rule 16). → [narrative-44-48.md#rule-44](narrative-44-48.md#rule-44)

45. **An address places a device only through the gate that owns it, and only a device nothing else can place** — for an asset with an IP address and NO MAC, `lastSeenSwitch` / `lastSeenAp` are derived by the `resolveIpUpstreamChain` sweep (`services/ipUpstreamChainService.ts`, scheduler role, every 10 min) along ONE chain: IP → owning FortiGate (`Subnet.fortigateSerial` first, `fortigateDevice` second, through `utils/fortinetParentKey.ts`) → THAT gate's `AssetArpEntry` → MAC → the `AssetMacTableEntry` port with the fewest MACs and the `AssetWirelessStation` carrying it. **Four refusals**: another gate's ARP row never counts (with no owning gate, exactly ONE reporting gate is accepted); two MACs at the address is `ambiguous`; a claim not current under rule 40 is skipped; ARP / FDB / station rows older than `EVIDENCE_FRESH_MS` (24h) are not evidence. **MAC-less assets ONLY** (`macAddress IS NULL`, infra types excluded). **The derived MAC IS adopted**, guarded by `partitionAdoptableMacs` (refused when another asset carries it, or two candidates resolve to it), in the same `$transaction` as the stamps, audited `asset.mac.adopted`, mirrored into `AssetMacAddress` as `ip-upstream-arp`. Stamps are never cleared and written only on change; set-based end to end. Rule 55 is the READ-side counterpart (IPAM as a last-resort parent). → [narrative-44-48.md#rule-45](narrative-44-48.md#rule-45)

46. **A device filter on an event automation filters the event's SUBJECT** — an `event` or `change` automation's `scope` selects which devices it fires ABOUT, and `runEventTail` requires the Event's asset to pass `scopeMatchesAsset`, tested BEFORE the fired-this-event stamp so a non-matching automation does not suppress its own reset. A FILTERED automation never fires on an event naming no asset (an integration, a user, the host) nor on one whose asset row is gone; an unconstrained one still does. **"Unconstrained" is asked first** — `scopeIsUnconstrained()` in `notificationTypes.ts` (`{allAssets:true}`, a bare `{}`, or a condition tree with no rules); it cannot fold into `scopeMatchesAsset`, which answers false for `{}`. The trigger is `scoped: true` in `buildSchemaCatalog` so the wizard saves the Devices step, and `previewRule` answers with the device list the filter selects. `ASSET_SCOPED_TRIGGER_TYPES` still excludes `event` (that list answers "is this automation about a device"). `triggerSignature` stays null for event and change (rule 18). → [narrative-44-48.md#rule-46](narrative-44-48.md#rule-46)
47. **A PostgreSQL client is chosen by the server's MAJOR and verified with `--version` before it is trusted — never spawned by bare name** — `pg_dump` refuses a server newer than itself, so `backupService.resolvePgTool()` reads `SHOW server_version_num`, looks for the versioned bin dir for that major (`/usr/pgsql-<N>/bin`, `/usr/lib/postgresql/<N>/bin`, the Windows install dir; a NEWER major is accepted, an older never), falls back to PATH only when nothing versioned exists, takes the NEWEST versioned client when the server's major cannot be read, then runs `--version` on its pick and compares majors (`src/utils/pgClientTools.ts`). An older `pg_dump` refuses the backup with both versions, the path and the fix in the AppError itself; `psql` only warns across majors. `deploy/update-linux.sh` carries the same logic (`resolve_pg_tool`); the RHEL installers install PGDG's versioned client and compare majors; `check:versions` flags a bare `dnf install -y postgresql`; CI pins `postgresql-client-17` and `postgres:17-alpine` as `postgres-major` sites; the Maintenance tab shows the resolved tools. Rule 51 is the other half — the parameters handed to that client. Pinned by `tests/unit/backupToolResolution.test.ts`. → [narrative-44-48.md#rule-47](narrative-44-48.md#rule-47)

48. **Nobody hands out authority they do not hold** — admin-equivalence is `users=fullwrite AND roles=fullwrite` (`isAdminEquivalentPermissions`), and a caller who lacks it may not create it. `assertNoPrivilegeEscalation(req, targetPermissions, subject)` in `api/middleware/permissions.js` refuses with **403** at the four minting points: `POST /roles`, `PUT /roles/:id`, `POST /users`, `PUT /users/:id/role`. **It is not four-eyes**: a caller already holding admin-equivalence is unaffected, and the check is skipped when the target set is not admin-equivalent. It is the mirror of the `lastAdminEquivalent` guard (`countAdminEquivalentUsers`) — that one refuses to DEMOTE the last admin, this one to PROMOTE into the tier. **The caller's level is read from the request's role snapshot** (`req.roleSnapshot` for a bearer token, `req.session.roleSnapshot` otherwise); no snapshot means NOT admin. The predicate is shared with `rankRole`'s group-mapping tie-break. `ssoProvisioning` and the seed are outside the rule — no escalating actor. → [narrative-44-48.md#rule-48](narrative-44-48.md#rule-48)

49. **An upgrade never refuses for want of a credential it can find itself, and never records one it has not proved** — `resolveUpgradeCredential` in `services/agentInstallService.ts` resolves, in order: the request's explicit `credentialId`, else the row's `installCredentialId`, else the Polaris-managed SSH deployment credential for the platform (`windowsSshOnboardingService.getOnboardingState`; darwin takes Linux's). **An id that no longer resolves counts as ABSENT** (the FK is `ON DELETE SET NULL`, and pre-column installs never had one); only an EXPLICIT unresolvable id is an error. **The transport follows the credential's TYPE, never `installTransport`** (which was backfilled `winrm` onto every pre-existing Windows row); a WinRM credential on a non-Windows agent is refused. **An adopted credential is written back on SUCCESS only**, with its transport; an operator override is never adopted. A row the fan-out still cannot upgrade writes `agent.upgrade_skipped`. **Upgrade only** — install, reinstall and uninstall still require a credential on file (`hasInstallCredential`). → [narrative-44-48.md#rule-49](narrative-44-48.md#rule-49)

50. **A response the app did not write is a response with the app's headers missing — an unmatched route is ANSWERED, never dropped to the framework's default handler** — `src/app.ts` mounts a catch-all after the `/api/v1` router that calls `next(new AppError(404, "Not found"))`, so `errorHandler` answers with the headers `buildHelmetOptions()` set; Express's `finalhandler` would replace the CSP with `default-src 'none'` (neither `frame-ancestors` nor `form-action` falls back to it) and echo the request path. **The 404 message is fixed, never built from the request.** Under `/api/v1`, `requireAuth` runs before any route match, so an unknown API path answers **401** to an anonymous caller and the JSON 404 only once authenticated — deliberate. The edge is the second half: `deploy/nginx/polaris.conf` emits HSTS itself, `proxy_hide_header`s the upstream's copy (two HSTS headers is non-compliant per RFC 6797 §8.1) and sets `server_tokens off`; a scan aimed straight at `npm run dev` cannot see that half, because no nginx sits in front of it. → [narrative-44-48.md#rule-50](narrative-44-48.md#rule-50)

73. **Planned downtime is reported as planned, and a scoped view of a window still reports the WHOLE window** — `NOT_IN_MAINTENANCE` keeps in-window assets out of every down/warning/stale feed (their `monitorStatus` is frozen, rule 16), so `maintenanceScheduleService.getActiveMaintenanceSchedules` (the `maintenanceSchedules` NOC feed, `maintenanceManagement:read`) and the Active Maintenance widget are the ONLY surfaces speaking about planned work. **It must not borrow outage vocabulary**: the pill is NEUTRAL via `setHeaderPills` (never `setHeaderCount`'s red fallback), matching the purple of the Status Summary tile and Status Map dots. **The asset filter narrows the LIST, never the window**: a schedule survives when ANY of its devices is in scope and is reported WHOLE, with `matchedCount` / `filtered` carrying the in-scope share; membership comes from open `AssetMaintenanceWindow` rows. `endsAt` is the SERVER's wall clock (the only displayable form) and `endsAtUtc` the same instant for countdowns. **Every verb is gated where the MODAL is** (`maintenanceManagement:write`), withheld on `/dash` and in a library preview; `fetchAssetsPage` returns early with no table to repaint. → [narrative-60-64.md#rule-73](narrative-60-64.md#rule-73)

74. **A field Polaris writes onto a device is budgeted where the operator types it, and the budget is the DEVICE's** — FortiOS holds 255 characters in a DHCP `reserved-address` description and Polaris spends part on `Polaris/<user>: <notes> [<hostname>]` (origin first, hostname bracketed LAST so `subnetRefreshService.extractHostnameFromDescription` can recover it). The room for notes is a COMPUTED budget (`reservationNotesBudget`, derived by composing with a one-character note), never a constant or a `maxlength`. The cap is `RESERVED_ADDRESS_DESCRIPTION_MAX`, and over-length input is REFUSED at save time (`assertReservationDescriptionFits`, 400 naming the budget, what was typed and the excess) before any device is touched — on create beside the MAC and deviceName checks, on edit before the MAC branch. Three boundaries: only on a push-eligible subnet; an edit is judged only when it TOUCHES `hostname` or `notes`, against what it will store; the truncating `slice` STAYS as the backstop for ungated rows (discovery-authored notes, the retry tick, infra auto-reserve). `public/js/reservation-notes.js` mirrors the arithmetic as an advisory counter, pinned to the server's function by `tests/unit/reservationNotesBudgetDom.test.ts`. → [narrative-60-64.md#rule-74](narrative-60-64.md#rule-74)

76. **Access is granted on the network profile the endpoint is actually on, and scoping it counts for nothing while a wider rule stands beside it** — installing OpenSSH Server makes Windows create `OpenSSH-Server-In-TCP`, any-source TCP/22 on the **Private profile only**, so a domain-joined endpoint (Domain profile) has sshd installed, running and unreachable. The Polaris rule `Polaris SSH (TCP 22)` was already `-Profile Any` and was never the blocked one; and because firewall rules are additive ALLOWS, `-RemoteAddress <polarisServerIp>` narrowed nothing while Windows' rule stood beside it. `services/sshOnboardingScript.ts` settles Windows' rule either way: with a server address it **disables** it, leaving the scoped Polaris rule as the only inbound path; without one it **widens** it to `Domain, Private` (never Public). Both paths are idempotent, the lookup is wildcarded by NAME (`OpenSSH-Server-In-*`) because the DisplayName is localized, and detection still judges no firewall (rule 72). Pinned by `tests/unit/sshOnboardingScript.test.ts`. → [narrative-76.md#rule-76](narrative-76.md#rule-76)

77. **A VIP describes an address; it does not claim it — and the status says every fact it has** — a FortiGate virtual IP is a THIRD fact about an address (`Reservation.vipInfo`), beside `sourceType` and `dhcpBinding` (rule 23). **A VIP address is claimable**: `isSupersedableByCreate` admits `sourceType: "vip"`, `releaseSupersededDhcpLeaseAt` releases it with NO device I/O and hands its snapshot to `persistReservationRow`, which stamps it onto the operator's new row; `interface_ip` is NOT admitted. Phase 3c's `manual` branch stamps rather than raises when the row already names this same VIP (by `name` + `device`), so a claimed VIP raises no conflict card. `decideVipDhcpBinding` writes `dhcpBinding` onto a `vip` row with `decideInfraDhcpBinding`'s three omissions verbatim (never `sourceType`, never `expiresAt`, `macAddress` fill-only). **The Status column reports both halves** through `_ipStatusPresentation` (the PDF and CSV exports read the same function): the VIP is a PREFIX — "VIP / Leased", "VIP / Reserved", "VIP / Conflict", `VS` for a virtual server — with the VIP's purple dot except on a conflict or a permanently failed push. **The per-subnet discover reads the VIP table** (`/api/v2/cmdb/firewall/vip` on the DHCP transport, `parseVipRow`), settled not awaited; an unreadable table skips every VIP decision and says so (rule 53). Retirement is scoped to snapshots naming THIS gate (rule 17). → [narrative-77.md#rule-77](narrative-77.md#rule-77)

78. **An automation may choose to speak for a silenced device, and then it must name who silenced it** — exactly ONE thing may opt out of dependency suppression's silence (rules 16, 37): the `monitorStatus == down` trigger, through `alertWhenDependencyDown` in its trigger JSON (read only via `notificationTypes.ruleAlertsWhenDependencyDown`, refused anywhere else and inside a multi-condition trigger, not part of `triggerIdentityOf`). An opted-in automation keeps its suppressed devices in evaluation and **fires on the suppression EDGE**: `resolveAssetStateReadings` hands each a synthesized `down` reading flagged `dependencyDown`. The alert **says DEPENDENCY DOWN** (`{dependency.summary}`, the ` · DEPENDENCY DOWN` subject tag, `dependencyTriggerSummary`) **and names who silenced it**: `dependencyTreeService.resolveDependencyBlame` walks UP (`dependency_test` / `maintenance` / `suppressed` / `down`, in that order) and the alert carries the UPSTREAM and the ROOT CAUSE, snapshotted on `Notification.dependencyDown` + `dependencyBlame`. **The flavour follows the asset's flag**: a plain Down alert whose device turns Dep. Down, or the reverse, is ENDED (`system:dependency-down` / `system:dependency-released`, no reset actions) and raised again in the other flavour. Not reached: a maintenance window still silences; reminders and escalation still pause; `clearSuppressedAlerts` never retires a `dependencyDown` row. A failed blame walk still lets the alert out, unnamed. → [narrative-78.md#rule-78](narrative-78.md#rule-78)

79. **An operator's removal of a MAC is a correction, not a suppression** — `DELETE /assets/:id/macs/:mac` deletes the `AssetMacAddress` row and nothing else: no tombstone, no exclusion list, no source-scoped ownership. If the network reports the address against the same asset again, the next discovery reconcile re-adds it, and that is the designed outcome — a stale association is never seen again and stays gone, while a MAC that keeps returning (a shared dock, a ZTNA-relayed identity) is a fact about the network the operator needs to see. Two obligations: the confirm SAYS the address may come back, and the primary-MAC recompute goes through `utils/macAddresses.ts` → `selectPrimaryMac()` so hardware-truth sources outrank sightings and a `[mac, macEnd]` range row is never promoted into `Asset.macAddress`. The grant is `assets:write`, and the browser control names the same key. → [narrative-79.md#rule-79](narrative-79.md#rule-79)

80. **Downtime Polaris itself causes is not an incident — and a silence it grants expires on its own** — an agent upgrade, reinstall or uninstall stops the agent, drops the WebSocket and writes `agent.disconnected` at WARNING, which the baseline automation watches. `services/agentInstallService.ts` takes a **MaintenanceHold** for the duration (`services/maintenanceScheduleService.ts` → `openMaintenanceHold` / `releaseMaintenanceHold`), suppressing through the gate every trigger honours (`assetCanTrigger`, rule 37). **A hold is a HOLDER, not a window**: the reconcile closes any open window it cannot re-derive from a live holder, so entry goes through the one path that parks the status, writes `maintenance.entered` and sweeps live alerts (rule 16). **Upgrade, reinstall and uninstall only** — a first install or a `/retry` has no running agent to disconnect. **Release is on REATTACH** (`services/agentChannelService.ts` → `attach`), not on the installer returning; an uninstall completes the hold; a FAILURE releases immediately. **Every hold carries `expiresAt`** (20 min upgrade / uninstall, 30 min reinstall), enforced by the reconcile (`endReason: "expired"`, warning logged). The operator and the decommission sweep outrank a hold (`operatorReleaseAsset` / `releaseAssetsForDecommission` delete the holder). Rule 80a is what lets a two-second hold suppress anything. → [narrative-80.md#rule-80](narrative-80.md#rule-80)

80a. **A silence is granted for when the event HAPPENED, not for when something got round to reading it** — the event tail applies a SECOND gate beside `assetCanTrigger`: was this asset inside a maintenance window at `ev.timestamp`, read from `AssetMaintenanceWindow` history (`services/notificationEngine.ts` → `loadMaintenanceSpansForEvents()` + `suppressedAtEventTime()`). `assetCanTrigger` reads the LIVE row, which is right for a threshold and wrong for a backlog judged up to 60 s late — a window shorter than the tick (an agent upgrade's is about two seconds wide) could suppress nothing at all. **One query per tick**, keyed by the batch's assets and bounded by its span. **Both boundaries inclusive.** **No grace after `endedAt`** — it would swallow `agent.upgrade_failed`, which `failUpgrade` writes immediately after dropping the hold. **Resets are not gated.** Does NOT cover `dependencySuppressed` (a live boolean with no history) nor `monitored` (correctly read live). → [narrative-80.md#rule-80a](narrative-80.md#rule-80a)

82. **A measurement of the host must not be dominated by the measurer, and a scheduling offset is not a way to protect one** — the agent's host CPU figure spans the WHOLE telemetry cadence: `internal/collectors/cputimes.go` reads the kernel's cumulative per-core counters each pass and reports the delta since the previous one, so the loop's cadence IS the averaging window and `TelemetryOnce` never blocks. The former `cpu.Percent(1*time.Second, true)` sampled one second in sixty and magnified the agent's own work ~60×, reading ~100% on a single-vCPU VM. **Loop phase offsets stagger when a pass STARTS and say nothing about how long it runs**, so they must never be relied on to protect a measurement. Three defaults to avoid: **not `cpu.Percent(0, …)`** (gopsutil's package-global baseline is shared by every caller — the baseline is ours in `cpuSampler`); **the aggregate is the summed-delta ratio**, not the mean of the per-core vector; **four conditions** (no baseline, a changed core count, counters not advancing, counters going backwards) fall back to one 250 ms blocking read. Per-pinned-program telemetry KEEPS its prime → sleep(300 ms) → read window. An installed agent keeps the old behaviour until upgraded. → [narrative-82.md#rule-82](narrative-82.md#rule-82)

83. **A serial belongs to one device and one owner; two claimants is a report, never a silent winner** — (a) **One managed device, two controller FortiGates**: `AssetSource` is unique on `(sourceKind, externalId)` and externalId IS the device serial, so a second gate OVERWROTE the first and the `fortinetTopology` / `discoveredByIntegrationId` stamps flipped every pass. The evidence is now stored: `AssetControllerClaim`, ONE ROW PER (device serial, claiming controller), re-asserted every discovery pass, swept by `duplicateSerialConflictService`. **REPORT-ONLY for (a)**: a completed rehome and a stale roster entry are identical observations; the card names both gates and when each last said so, and is self-cleaning after `CLAIM_FRESH_DAYS` (2). **HA is ONE gate**: claimants fold onto the firewall asset via `resolveInfraParentAsset`, never a hostname compare. (b) **One serial, two Asset rows**: the only verb is the merge (`assetMergeService.mergeAssets`, `assets:fullwrite`), and it is taken AUTOMATICALLY by `mergeDuplicateHostnameAssets`' serial pass (`normalizeSerialKey`, `isUsableSerial`, `MAX_PLAUSIBLE_DUPLICATES` = 8) — through `mergeAssets`, like the card's own verb, so both records' sources and the agent enrolment survive — a card that SURVIVES means the merge declined it. Placeholder filtering at every write point is rule 84. The discovery index keys `bySerial` by `normalizeSerialKey`, as do the three Fortinet RMA guards. Both flavours stamp `conflict.detected` and dedup on dismissal ((a) the claimant set, (b) the member set). The status filter drops only `decommissioned` and `disabled`. → [narrative-83.md#rule-83](narrative-83.md#rule-83)

84. **A value that cannot identify a device is refused where it would be WRITTEN, not where a sweep would read it** — Windows publishes no serial in the registry, so the agent's fallback took `SystemSKU`, a MODEL code identical across a model line; `polaris-agent` ranks FIRST for `serialNumber` in `utils/assetProjection.ts`, so it overwrote real serials, rule 83 read the line as duplicates, and `utils/hardwareIdentity.ts`'s `indexUniqueBy` existed only to work around our own bug. **A serial is tested at EVERY write point**: `usableSerial()` in `agent/internal/collectors/serialnumber.go` before it goes on the wire (all platforms); `obsSerial` in `utils/assetProjection.ts` so every `SERIAL_RULES` pick FALLS THROUGH to the next source (a VALUE filter — the priority order is untouched); a clear at `POST /system-info` (+ `asset.serial.cleared`) for a stored placeholder no source can replace, because the projection's write-back never writes a null. **One list, asserted not asked for**: the list, floor and repeated-character shape live once in `utils/serialNumber.ts`, and `tests/unit/serialNumber.test.ts` PARSES the .go file to assert set equality. **`indexUniqueBy` stays** — ambiguity in the data is not an identity. A new `SERIAL_RULES` entry MUST use `obsSerial`; a new collector applies `isUsableSerial` before the value reaches an `AssetSource` blob. → [narrative-84.md#rule-84](narrative-84.md#rule-84)
