## Rule 192 — A switch, firewall or access point Fortinet does not manage is placed like an endpoint when the infra graph gives it no parent

**The report (2026-11-17).** "I have some Cisco fibre channel switches that aren't showing up in the device list for one of my sites. The last seen firewall is correct and the last seen switch is correct and already in the device grouping." Then: "the last seen switch doesn't appear to affect the dependency tree of these switches."

**Why.** Polaris split assets on TYPE: `switch`, `firewall` and `access_point` were "Fortinet infrastructure" (`FORTINET_INFRA_ASSET_TYPES`) and everything else an endpoint. The infra half parents from FortiLink controller stamps, interface naming and LLDP; the endpoint half from `lastSeenSwitch` / `lastSeenAp` / sightings / IPAM. A Cisco MDS is typed `switch` but has no controller stamp and, on an FC fabric, usually no LLDP to a FortiSwitch, so it fell between the halves: no parent (never Dep. Down behind its FortiSwitch), and the topology payload — FortiSwitches as `switches`, everything else as `endpoints` with the infra types excluded — carried it nowhere, so the Topology map's Device List never offered it.

**The decision.** Offered (a) treat such a device as an endpoint, or (b) keep it infrastructure and add `lastSeenSwitch` as the infra half's weakest signal plus a separate topology list, the operator chose (a). It is implemented as a FALLBACK rather than a re-typing: a non-Fortinet switch can itself be a parent — an endpoint whose `lastSeenSwitch` names the Cisco switch hangs under it — so removing it from the infra inventory would orphan everything behind it. Only the unparented ones join the endpoint half, after the infra graph is built.

**Guards.** A layer-1 root (a firewall the graph roots) stays a root: making it a child would reorder the reconciler's layer walk. Two devices placed this way never parent each other — two FC switches each naming the other as last-seen would loop the suppression walk. The fallback is self-healing: a later LLDP or interface edge removes the device from the extra set, and the endpoint pass deletes its row by diff.

**Rejected.** Re-typing third-party switches as endpoints (orphans what is behind them); a union of infra and endpoint parents (rule 45's single-parent ladder exists because a switch and its gate are in series); a type-based rule keyed on manufacturer (a FortiSwitch added by hand without discovery would be misread — the Fortinet role stamp is what the infra half actually needs).
