│       ├── geoPolygon.ts            # Pure polygon-VS-polygon geometry — the sibling `geo.ts` deliberately does NOT grow into (that file is a 112-line leaf on the discovery hot path). `polygonContainsPolygon(outer, inner)` answers `contains | overlaps | disjoint | equal-area | approximate`, and is what makes map-region LEVELS derivable from nesting. Three tests in order, all three needed: a bbox prefilter (rejects nearly every real pair in O(1)); every vertex of `inner` inside-or-on `outer`, early-exiting on the first outside vertex (that early exit is why a rejected candidate costs ONE point test rather than V_inner of them); and no edge of `inner` PROPERLY crossing an edge of `outer` — because all-vertices-inside is wrong for a CONCAVE outer, where a child can have every vertex inside a C-shaped parent while its body cuts straight across the notch. `pointRingPosition` supplies the `"boundary"` answer `pointInPolygon` documents as unspecified, and containment counts boundary as inside, so a child drawn with a vertex snapped onto its parent's edge is still a child; `segmentsProperlyCross` returns FALSE for a shared endpoint and for collinear overlap for the same reason (a child sharing an edge with its parent is nesting, not overlap). `equal-area` (within `AREA_EPS_REL`) is what makes containment a STRICT partial order and therefore acyclic — no pair can each contain the other, so levels can never cycle. A shared accumulating `WorkBudget` bounds one hierarchy build (200 regions at the 1000-vertex schema cap is ~10⁸ primitive ops); on exhaustion containment degrades to the bounding-box answer marked `approximate` rather than stalling a request, and deterministically so as long as the caller iterates candidate pairs in a stable order. Areas are square DEGREES — comparison-only, never surfaced to an operator. Antimeridian crossing is out of scope, the same documented limitation `geo.ts` carries.
│       ├── regionHierarchy.ts       # Pure derivation of the map-region containment FOREST and a level per region from polygon nesting alone (`buildRegionHierarchy({id, polygon}[])` → `{byId, rootIds, maxLevel, warnings, truncated}`). Input is ids + polygons ONLY — no names, no colors — so it stays testable and can't drift into a service. **Carries BOTH `depth` and `level`, and they are not interchangeable:** `depth` counts inward from the outermost ring (0 = top-level) and is always gap-free, while `level` counts outward from the leaves (1 = contains nothing) and CAN have gaps — a parent holding one bare leaf and one 3-deep chain is L4 with children at L1 and L3 and no L2 beneath it. `level` is the operator's mental model and what the region tree displays; `depth`/`ancestorIds` is what code routes on, so **never compute a routing target with `level + 1` arithmetic**. Two swappable `LevelRule`s: `levelByDepth` (the default — ANY container is strictly above its children, the only reading where level implies containment rank, which is what "operators get the leaf, managers get the container" needs) and `levelByBranchingCount` (the literal "more than one child" wording, kept and tested but NOT default because it puts a single-child wrapper at the same level as its child, so level can no longer tell a front-line region from its manager wrapper). Immediate parent = the SMALLEST container; each unordered pair is tested exactly once with the larger ring as the candidate container (a strictly-contained ring always has strictly smaller area), which is also what makes a budget-degraded result deterministic. Warnings are `overlap | duplicate | degenerate | self-intersecting | ambiguous-parent | approximate | cap-exceeded` — and two of them need real geometry rather than the raw relation: `equal-area` alone cannot tell a genuine duplicate from two same-sized regions in different states (which must warn about NOTHING) or from two same-sized regions that partly overlap, and `overlaps` alone fires on a child sitting in a concave parent's notch, which never touches it. A real edge crossing is the only signal reported as overlap. Above `MAX_HIERARCHY_REGIONS` (500) the forest is not computed at all and every region comes back flat with `truncated: true`.

│       ├── burstPing.ts             # BATCHED ICMP BURST measurement — `burstPing(targets[])` returns per-target {sent, received, avgRttMs} so packet loss is a real ratio of PACKETS rather than a ratio of status-poll outcomes (which can only read in steps of 1/N over the window's N polls, and shares its evidence with down detection).
