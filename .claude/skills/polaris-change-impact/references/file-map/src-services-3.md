Only the interface STATE fields, deliberately: an `ifInErrorRate` / `ifOutBps` alert plausibly correlates with device load and keeps its graphs. What replaces them is alertInterfaceService's LLDP block. `isSdwanScopedAlert(metric)` / `SDWAN_SCOPED_METRICS` is that same decision one layer out, and the reason the SD-WAN charts exist: all five SD-WAN triggers (three health-check metrics + the two service-rule state fields) DROP cpu / memory / responseTime / probeLoss and render `chart.sdwanLatency` / `chart.sdwanJitter` / `chart.sdwanLoss` from AssetPerfSlaSample instead, because a FortiGate losing 40 % to wan1 is answering its own probes perfectly and its device graphs are a healthy firewall printed under a degraded link.
