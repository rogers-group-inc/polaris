│   │   ├── seedManufacturerProfiles.ts # One-shot startup (Slice 6a): converts the hardcoded `VENDOR_TELEMETRY_PROFILES` constant into `ManufacturerProfile` + `ManufacturerProfileMetric` + `ManufacturerProfileMetricOverride` rows. │   │   ├── seedBaselineAutomations.ts # One-shot startup: seeds the baseline automations (NotificationRule rows) in three independently-markered sets. Set 2 (12 rules, marker `Setting.seedBaselineAutomationsV2SeededAt` — its own key so pre-v2 installs pick it up without duplicating set 1) covers the notable system-generated Event families with event-trigger automations: discovery failed/aborted, quarantine + reservation push failures (queued + permanent), agent disconnected / upgrade failed, capacity escalations (detailsMatch direction=escalated), ip-override conflicts, auto-decommissions, HA standby down, login lockouts — all enabled, in-app only, storm-proofed with a `cooldownSec` plus a real reset — a timer, or (where Polaris writes the counterpart event) `reset.mode="event"` on it: agent disconnected clears on `agent.connected`, discovery failed on `integration.discover.completed`, agent upgrade failed on `agent.upgrade_succeeded` (relies on the engine's event-tail cooldown + timed-clear + counterpart-reset passes); glob-vs-writer pinning in seedBaselineAutomations.test.ts. SEED-ONCE per set, NOT self-heal: once a marker is stamped that set never re-runs, so a rule the operator edits/DELETES stays gone. Built through `ruleInputSchema` + `createRule` (canonical v2 shape); numeric rules auto-clear with hysteresis at the widget's warning level. Delete a set's marker + restart to force a re-seed (resurrects that whole set). **V3 (down detection)** is a THIRD marker (`seedBaselineAutomationsV3SeededAt`) and differs in kind: it is COMPUTED from live data, not a static array. An edited row is kept + flagged (`automation.seed.v3_retained`): it still governs at `DEFAULT_MISSED_POLLS`, and the operator must be told the count is theirs now. Order is CREATE-then-retire (the reverse leaves a window with zero down automations = a momentarily blind fleet), and it refuses to retire if the replacement failed to save. Known gap, logged rather than hidden: `scopeRank` doesn't rank `integrationIds`, so one class with different thresholds across two integrations collapses to the more-sensitive value + an `automation.seed.threshold_conflict` warning Event.. **V5** (`migrateLossCeilingV5`, marker `seedBaselineAutomationsV5LossCeilingSeededAt`) retrofits `ignoreAtOrAbove: 90` onto existing installs' packet-loss automations — the seed marker means they never re-seed, and with the loss anchor removed (rule 29) an all-assets loss rule with no ceiling trails a second alert behind every outage. Bounded like V3's retire step: only probeLossPct triggers stating NO ceiling, and only rules never edited (updatedAt === createdAt); an edited one is left alone and NAMED in a warning Event, because narrowing someone's tuned alert silently is worse than leaving it noisy
