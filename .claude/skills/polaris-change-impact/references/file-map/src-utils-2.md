Shared utilities.

│       ├── arpTable.ts             # Pure (no I/O) shaping of one FortiGate's ARP table before it reaches asset_arp_entries. `prepareArpRows` normalizes the MAC to colon-uppercase, folds an empty interface to NULL (FortiOS answers "" for an entry it cannot attribute, and a port named "" would render as real), dedupes on (ip, mac, ifName) keeping the FRESHEST row — a known age beats an unknown one, then lower wins, since FortiOS reports one binding twice when an interface and its VLAN child both resolve it — orders interface-then-numeric-IP so the cap slices deterministically, and caps at ARP_ROWS_PER_ASSET_CAP (4000) reporting what it dropped. Two MACs claiming one IP are KEPT as two rows: that is a duplicate-address finding, not a dedupe. `arpRowKey` is the (ip, mac, ifName-or-"") business key the firstSeen carry-forward and the writer's own uniqueness both use; `groupArpRowsByDevice` buckets a run's flat rows by lowercased FMG device name. │       ├── arpNeighbors.ts         # Pure (no I/O) decoding of a device's IP neighbour cache out of IP-MIB SNMP walks — the SNMP half of the ARP Table tab. Two generations, preferred then fallback like the Q-BRIDGE→BRIDGE FDB pair: `ipNetToPhysicalTable` (RFC 4293, IPv4 ARP *and* IPv6 NDP) then the deprecated `ipNetToMediaTable` (RFC 1213, IPv4 only). The ADDRESS is decoded from the OID INDEX in both cases, which on the modern table is the only place it exists — its index objects are not-accessible, so walking them answers nothing — and `parsePhysicalIndex` therefore has to honour the RFC 4001 length prefix (`<ifIndex>.<addrType>.<len>.<bytes…>`); a decoder that assumes 4 bytes invents addresses on every IPv6 row rather than failing. `buildArpNeighbors` drops rows whose MAC or index does not decode, type `invalid(2)`, and state `invalid(5)`/`incomplete(7)` (an incomplete entry is a resolution attempt in flight, so storing it would claim a binding that never resolved), while KEEPING `stale(2)` and `local(5)`. An unresolved ifIndex yields `ifName: null` rather than dropping the row. `ageFromLastUpdated` turns `ipNetToPhysicalLastUpdated` (a sysUpTime STAMP, not an age) into seconds and returns null — never 0 — when either value is missing or the stamp is in the future, since 0 would read as "just refreshed". `arpNeighborsFromFortiosRest` maps the REST endpoint's rows onto the same shape so the writer never learns which transport produced them. Consumed by monitoringService (`collectArpNeighborsSnmp`) and services/arpTableService.ts
│       ├── oidCompare.ts            # Pure (no I/O) numeric OID comparison: compareOids(a, b) (component-wise numeric, prefix-before-extensions — SNMP lexicographic order) + makeOidMonotonicGuard() (stateful per-walk guard: advance(oid) returns false the moment an agent returns an equal-or-lower OID). Backs the walk-loop defense in both monitoringService walk paths (internal snmpWalk + operator snmpWalkRaw): net-snmp's subtree/walk re-anchors on the last varbind with NO non-increasing check (and its backwardsGetNexts strict mode passes EQUAL OIDs), so a broken agent that echoes the queried OID back on GETBULK (field case: ControlByWeb X-4xx) would otherwise loop forever — in the internal walk the echoed base OID never matches the `baseOid.` prefix filter, so not even the row cap would trip, and the walk would hold the per-host SNMP gate indefinitely. On trip: AppError 502 naming both OIDs + "try an SNMP v1 credential or firmware update" (surfaced verbatim by the SNMP Walk tab).

The narrow exception to snmpIdentity.ts's refusal to derive a model from free text: a vendor whose layout is DOCUMENTED is parsed, everything else yields undefined. Every parser anchors on the vendor token (AXIS field 1 is an operator-settable device name), claims a field only when it is shaped right, and yields nothing at all — never `{manufacturer}` alone — when the layout does not read. The reading becomes an `snmp-sysdescr` AssetSource row, so WHETHER it wins is `assetProjection.ts`'s priority call, not this file's; `decideDescrAdoption` was retired with that cutover (two places answering "may this overwrite that?" is how two writers end up trading values every cycle).
│       ├── snmpIdentity.ts          # Pure (no I/O): turns an SNMPv2-MIB **system group** walk into asset fields for a network Discovery (business rule 34) — `parseSnmpIdentity(rows)` over what `snmpWalkRaw(host, config, "1.3.6.1.2.1.1", n)` returns, plus `vendorFromSysObjectId` / `vendorFromSysDescr` / `enterpriseFromSysObjectId` / `SYS_OIDS`. Nothing did this before: every other system-group reader in the repo takes exactly ONE object (`sysUpTime` for the reachability probe, `sysLocation` over FortiOS REST), and the only sysDescr/sysName elsewhere are LLDP *remote*-neighbour columns describing someone else's device. Four decisions. (1) **The vendor table is small and explicit and an unknown arc yields NOTHING** — the enterprise registry has tens of thousands of entries, and a wrong manufacturer is a field an operator never re-checks while an empty one is a field they fill in; the seeded arcs mirror `oidRegistry.BUILT_IN_OIDS` so the two can't disagree about who 12356 is. (2) **sysObjectID outranks sysDescr, EXCEPT for the generic agent arc** — the arc is a registered assignment and a vendor word in the description can name the OS on someone else's hardware, but Net-SNMP's own arc (2021 / 8072) names the AGENT by definition, so a Linux-based PDU running net-snmp takes the description's vendor instead. (3) **Unconfigured-agent placeholders are dropped** ("Sitting on the Dock of the Bay", "Me <me@example.org>", unknown / not set / n/a): storing them puts a site that doesn't exist into an asset's Location — the placeholder-serial rejection in utils/hardwareIdentity.ts, same reasoning. (4) **A `model` comes from a FORMAT, never from a pattern** — the system group has no model object and a cross-vendor regex over sysDescr fails silently on the vendors it wasn't written for (the entPhysicalIndex==ifIndex equivalence, again), so `model` / `osVersion` / `productType` are filled in ONLY by `utils/snmpDescrIdentity.ts`, from the vendors whose delimited layout is documented; a device outside that table reads exactly as it did before those fields existed, and a vendor scalar via `vendorTelemetryProfiles`' `modelIdentity` is still the better source where one exists. │       ├── interfaceIdentity.ts      # Pure (no Prisma): which name IS an interface, and which merely DESCRIBES one. `buildInterfaceIdentity(rows)` turns an asset's current-state `asset_interfaces` rows into `{ names, labelToName }`; `canonicalInterfaceName` / `canonicalizeInterfaceRows` / `canonicalizeInterfacePins` map a label back onto the port that carries it. Tests: tests/unit/interfaceIdentity.test.ts, tests/integration/interfaceIdentityReconcile.test.ts
│       ├── snmpInventory.ts          # Pure: decodes an interface list (`parseScanInterfaces`) and storage-mount list (`parseScanStorage`) out of raw IF-MIB / ifXTable / hrStorageTable walks, for a network Discovery. │       ├── assetTypeMatch.ts       # Pure (no DB) device-type INFERENCE layer: the operator-editable rules (`AssetTypeDef.matchRules` / `matchContexts` / `matchPriority`) that decide which discovery-time facts land a device in which bucket. Replaced two hardcoded predicates — `inferAssetTypeFromOs` (discoveryEngine, directory sources) and `assetTypeForHit` (networkScanService, Network Discovery) — both of which now delegate here; `DEFAULT_TYPE_MATCHING` transcribes them verbatim and migration `20260901010000_asset_type_match_rules` seeds the same values onto existing rows, so the cutover is a no-op until an operator edits a rule (`tests/unit/assetTypeMatch.test.ts` pins that by holding the resolver against reimplementations of both old ladders). **Contexts are per-type, not global**: server/workstation were directory-only and firewall/switch/access_point/router/printer were scan-only, and collapsing them would silently type an AD computer "printer" off its OS string. **Rules are a nested AND/OR tree** since 2026-09 (`{op, children}` over and/or/none/notAll, leaf `{field, operator, value}`) — the automations device-filter grammar, edited in the shared `PolarisConditionBuilder` off `matchConditionMeta()`, which publishes the catalog in `scopeConditionMeta()`'s shape and words the six overlapping operators identically (pinned by `tests/unit/assetTypeMatch.test.ts`). `conditionMatches` evaluates it with the same boolean identities as `evaluateScopeCondition` (`none` = ¬or, `notAll` = ¬and); the two evaluators stay separate because one filters stored Asset rows and this one reads facts about a device with no Asset row yet. Leaf semantics: case-insensitive, `any` = the space-joined facts, negation on the OPERATOR (`notContains` / `notStartsWith` / `notRegex`, never a `none` group around a leaf), and an ABSENT fact never matches EITHER polarity (at discovery time missing means *not yet known*, so letting absence satisfy a negation would let one field outage re-type a fleet — and it is the one place this evaluator deliberately disagrees with the device filter, where `notContains` on a NULL column is satisfied). `normalizeMatchRules` folds every pre-2026-09 spelling forward on READ and nothing is migrated: flat `{clauses}` → an OR tree, leaf `op` → `operator`, `starts_with`/`ends_with` → `startsWith`/`endsWith`, `negate: true` → the operator's negative twin. It also PRUNES (valueless leaf → gone, empty group → gone, empty root → null), which is what stops `and([]) === true` from handing a type the whole fleet when an operator deletes the last condition; `MATCH_OPS` leads with `contains` rather than copying the device filter's order, because the shared builder defaults a new row to the first operator and `equals` against a vendor OS string silently matches nothing. Regexes are compile-checked at WRITE time — the resolver runs per device per run, so a typo must not be able to throw into it — and a stored pattern that still fails to compile is treated as no-match. Carries its own registry cache (`setAssetTypeMatchRegistry`, installed by the same `assetTypeService.refreshCache()` that fills `assetTypes.ts`), whose **never-loaded state falls back to `DEFAULT_TYPE_MATCHING`** rather than to nothing: `seedAssetTypes` only runs where `runsMigrations` is true, so the split-role DISCOVERY process reaches the resolver cold and answering "nothing matches" there would file a whole run under Other. `startBackgroundJobs` warms it on every role and `runDiscovery` re-reads it per run. Also exports `AUTHORITATIVE_TYPE_SOURCES` — the catalogue of paths rules CANNOT reach (Fortinet controller CMDB, vCenter inventory, Azure Arc, an operator's own edit), served at `GET /asset-types/match-schema` and rendered by the Device Types card so an operator can see which buckets their rules will never affect.
