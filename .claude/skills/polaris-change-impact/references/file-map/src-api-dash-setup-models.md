# File map — src/ root, src/dash/, src/api/, src/setup/, src/models/

The Express app, routers, middleware, the dash listener, the first-run wizard and shared models.

A slice of the repository tree (`polaris/` is the root; `│` continuation bars are relative to it). Per-file purpose notes follow each entry.
```
├── src/
│   ├── index.ts                     # Entry point
│   ├── config.ts                    # App config / env vars
│   ├── db.ts                        # Prisma client singleton
│   ├── utils/imageSize.ts           # pngSize / jpegSize / imageSize — pixel dimensions parsed from the file header (PNG IHDR; the JPEG marker chain walked to the first real SOF, skipping DHT/JPG/DAC inside the same marker range). Needed by brandLogoService to place the accent overlay: preserveAspectRatio can fit an image into a box but can't say what box the image already is. WebP deliberately returns null (resvg can't embed it, so there's no accent path anyway). Never throws.
│   ├── utils/imageMagic.ts          # detectImageMagic(buf) → ".png" | ".jpg" | ".webp" | null from magic bytes. Extracted from the branding-logo upload route; also used by appIconService to re-sniff on read (never trust the extension, and resvg can't decode an embedded WebP).
│   ├── utils/publicUrl.ts           # Parse POLARIS_PUBLIC_URL → public-facing port (nginx fronts TLS)
│   ├── utils/ipAllocation.ts       # Pure free-address selection behind the IP panel's Auto-Allocate modal (single AND multiple mode): `selectAvailableIps(hosts, taken, count, contiguous)` → `{ ips, largestRun, availableCount }` over an ordered, gapless host list — which is what lets adjacency in the ARRAY stand in for adjacency in the address space, and is the only assumption it makes. No Prisma, no I/O and no IP arithmetic (that stays in `utils/cidr.ts`); it only compares and slices strings, so the contiguity rules are unit-testable on their own. Two decisions live here: contiguous returns the EARLIEST fitting run rather than the largest (a later, roomier gap is not what "next available" means), and an unsatisfiable request returns an EMPTY list plus the two stats rather than a partial one — "allocate 12" half-done is not an outcome anyone asked for, so `reservationService.findNextAvailableIps` turns the stats into the 409 an operator reads ("the largest available run is 6").
│   ├── utils/fortiswitchCmdb.ts     # Pure parsers over the switch-controller managed-switch CMDB `ports` array (shared by monitoringService + the FMG/FortiGate discovery collectors, dependency-free to avoid an import cycle): `buildFortiswitchTrunkMembers` (trunk→physical-member map; LACP `members` + FortiLink auto-ISL `isl-local-trunk-name`) and `findFortiswitchUplinkPorts` (a switch's physical uplink port to its controller FortiGate via `fortilink-port` / `fgt-peer-device-name`)
│   ├── utils/portVlans.ts         # Pure Q-BRIDGE-MIB (RFC 4363) per-port VLAN decoding: `decodePortList` (PortList OCTET STRING → dot1dBasePort numbers; octet 0's MOST-significant bit is port 1) and `derivePortVlans` (dot1qPvid + the per-VLAN egress/untagged bitmaps → per-port {nativeVlan, taggedVlans}). The decision worth isolating: `dot1qVlanStaticUntaggedPorts` is often a verbatim COPY of the egress column (observed on FortiSwitch, 2026-08), and the RFC subtraction against a copy leaves EVERY port with an empty tagged set — a working trunk silently reported as carrying nothing. The untagged column is therefore believed only when it is a STRICT SUBSET of egress; otherwise the port's own PVID does that job. A port's native VLAN is never listed among its tagged VLANs either way
│   ├── utils/locationCodes.ts       # Pure parser for physical-location codes embedded in FortiSwitch/FortiAP admin descriptions (`b:` building / `f:` floor / `r:` room / `jb:` junction box). Case-insensitive keys matched at start-of-string or after whitespace; resolved server-side (Asset.description's codes when present, exclusively; else the device description's — notes are never a source) so the topology endpoint ships final strings and the browser never needs the grammar
│   ├── utils/linearTrend.ts         # Least-squares trend helpers for the storage-forecast surfaces: `leastSquaresSlopePerDay` (OLS slope in units/day — the JS reference implementation of the SQL regr_slope fit) + `daysUntilFull` (remaining/slope projection; null for flat/shrinking mounts or unknown capacity, 0 when already over)
│   ├── dash/
│   │   └── dashServer.ts            # The Dash wallboard listener — a small standalone Express app serving the UNAUTHENTICATED read-only /dash surface in its own process (POLARIS_ROLE=dash; also boots in-process under role "all" on POLARIS_DASH_PORT, default 3001). Middleware chain (order load-bearing): dashConfig-Setting kill-switch (10s TTL) → source-IP gate (`ipScope`: rfc1918+loopback / all / custom-CIDR-allow-list via isSourceAllowed; an UNAUTHORIZED source is DROPPED — socket destroyed, no response — so a scanner can't confirm the wallboard exists) → shared helmet CSP → GET/HEAD-only 405 → rate limit (general 600/5min; /weather/* rides the dedicated dashWeatherLimiter 4000/5min since one radar refresh is hundreds of tile GETs) → readonly-role snapshot stamped on req.roleSnapshot → /dash page + /dash/api/v1 (exact-path allowlist over the REAL dashboard/reservations/map routers + synthetic /auth/me + public branding, plus a /weather/ prefix rule for the parameterized weather-proxy paths) → /uploads static (custom branding logo, so dash-boot.js can swap the page favicon when hit directly) → public static. buildDashApp(opts) is the supertest seam.
│   ├── api/
│   │   ├── router.ts                # Express router aggregator + auth guards
│   │   ├── middleware/
│   │   │   ├── auth.ts              # Session auth + RBAC middleware
│   │   │   ├── csrf.ts              # Synchronizer-token CSRF protection (`polaris_csrf` cookie + `X-CSRF-Token` header)
│   │   │   ├── rateLimits.ts        # Shared per-route rate limiters (TOTP code attempts, OIDC login kick-off, admin maintenance/backup, agent bearer router + binary downloads). The login limiter predates this file and stays in `src/app.ts`.
│   │   │   └── errorHandler.ts      # Global error handler
│   │   └── routes/
│   │       ├── auth.ts              # Login, logout, Azure SAML SSO
│   │       ├── blocks.ts            # IP block CRUD
│   │       ├── subnets.ts           # Subnet CRUD & allocation
│   │       ├── reservations.ts      # Reservation CRUD
│   │       ├── utilization.ts       # Reporting endpoints
│   │       ├── dashboard.ts         # `/dashboard/summary` + `/dashboard/noc-summary`. Both accept a subset param so each widget fetches only what it renders (`?sections=blocks|recent|assetTypes|monitorAlerts` on summary, `?feeds=<feed,...>` on noc-summary; absent = full legacy shape), and both serve every section/feed through a short server-side TTL cache (`utils/ttlCache.ts`, 10s = `NOC_FEED_CACHE_TTL_MS`) so concurrent widgets/tabs/kiosks share one computation. `summary` sections: blockUtilization from utilizationService.getGlobalUtilization, recentReservations from utilizationService.getRecentManualReservations (sourceType=manual only by default; cache key carries the recentLimit/sourceTypes params), assetTypeCounts via prisma.asset.groupBy (excluding decommissioned/disabled), and monitorAlerts via prisma.asset.findMany filtered to monitored + status in (warning, down), ordered by monitorStatusChangedAt desc nulls-last, capped at 50. `noc-summary` delegates to `nocDashboardService.getNocSummaryPayload` (feed registry + per-feed cache + `resolveFilteredAssetIds`); the route only parses params (`?assetTypes=server,switch,…` = the ENABLED built-in types, `?regionTags=East,West` = region names from the widget's Regions scope ("My regions" or a Selected-regions pick), `?fortigates=SITE-FG1,…` = FortiGate device names from the widget's FortiGates scope (assets behind any named gate; `__none__` = the "(No FortiGate)" gate-less entry), `?limit=` row cap, `?feeds=`) and resolves permissions. Both endpoints are permission-filtered, never 403'd (the dashboard is the redirect target for users bounced off gated pages): ipBlocks≥read → blockUtilization, reservations≥read → recentReservations, assets≥read → assetTypeCounts + monitorAlerts + all noc-summary asset sections, events≥read → noc-summary recentReboots, alerts≥read → activeAlerts (Notification-sourced since 2026-08; every role was seeded that key at read by migration 20260628000000, so no kiosk token lost the feed); denied sections return empty arrays (and never enter the cache), token callers get all-empty.
│   │       ├── users.ts             # User CRUD & role management
│   │       ├── integrations.ts      # FMG / FortiGate / Windows Server / Entra ID config CRUD, connection tests, Query API proxy, discovery trigger/cancel routes (thin route — the discovery engine itself lives in services/discovery/discoveryEngine.ts)
│   │       ├── assets.ts            # Device inventory CRUD, PDF/CSV export
│   │       ├── map.ts               # Device Map: site list, search, per-FortiGate topology graph (thin route — graph construction lives in services/topologyGraphService.ts) + shared topology-layout writes
│   │       ├── applicationMap.ts    # Application Map: GET / (the connectivity graph payload from applicationMapService, gated applicationMap=read) + PUT/DELETE /layout (shared ApplicationMapLayout drag positions, gated applicationMap=write, audited application_map.layout.saved/reset). Mounted at /application-map. The per-asset connections read lives on assets.ts (/assets/:id/process-connections).
│   │       ├── mapRegions.ts        # CRUD for operator-drawn map regions (admin/networkadmin); reconciles `region:<name>` tags
│   │       ├── weather.ts           # Status Map weather proxy: RainViewer radar frame list + tile proxy + Open-Meteo temperature (server-side cached; widget falls back to the CDNs directly). Mounted on the main router AND the Dash listener.
│   │       ├── events.ts            # Audit log, syslog, SFTP archival
│   │       ├── notifications.ts     # Triggered-alert list (region-scoped) + acknowledge + clear. Gates alerts:read|write|fullwrite. Canonical mount /alerts; deprecated alias /notifications. Thin over notificationService.
│   │       ├── automationScripts.ts # AutomationScript registry (Automations → Scripts tab) + run history. Mounted at /automations/scripts BEFORE /automations (so "scripts" is never a rule id). Gated automationScripts: read = list/get + /runs + /runs/:id; fullwrite = CUD + POST /:id/test-run (server-target only, enqueues a run → 202 {runId}, client polls /runs/:id). Backed by automationScriptService.
│   │       ├── notificationRules.ts # Automation (rule) CRUD + /schema (builder vocabulary, with `dimensionPickers` merged in from notificationDimensionService — merged HERE, not inside buildSchemaCatalog, because notificationTypes importing the dimension service would cycle through the engine — plus `stateProbes` from manufacturerProfileService.listStateProbes(), merged here for the same reason: the builder needs each state probe's NAME and its two state LABELS so a 0/1 condition renders as "is Alarm" instead of "== 1") + POST /dimension-values (values the draft's own scoped devices report for one metric dimension; automationManagement:read) + /preview (dry-run). Gated automationManagement; POST/PUT carrying any script action (top-level or escalation tier) additionally require automationScripts=fullwrite (assertScriptActionPermission). Canonical mount /automations; deprecated alias /notification-rules. Validates via ruleInputSchema; logic in notificationRuleService + notificationEngine.previewRule.
│   │       ├── maintenanceSchedules.ts # Maintenance-schedule CRUD (Assets → Maintenance modal) + POST /preview (target-filter dry-run → capped device list + total, monitored-only) + GET /occurrences?from&to (calendar tab: every schedule's occurrences expanded over a day range). Gated maintenanceManagement (read for list + occurrences, fullwrite for CRUD/preview). Thin: Zod outer shape here; recurrence + criteria validation and the inline reconcile live in maintenanceScheduleService.
│   │       ├── contacts.ts        # Address-book CRUD (Automations → Address Book) + GET /search (the unified recipient typeahead: Polaris users ∪ contacts) + POST /preview (device-filter dry-run). Reads gated `contacts:read`; writes use `requireOwnership("contacts")` + `assertOwnership` so a write-level caller edits/deletes only rows they created. `/search` + `/preview` declared BEFORE `/:id` so the literal paths aren't captured as ids. Thin: criteria validation, email normalization and audit Events live in contactService.
│   │       ├── networkScans.ts    # Saved network **Discovery** CRUD + runs, mounted /api/v1/network-scans behind a `networkScan:read` FLOOR on the whole router (the `/map` precedent — three of its read routes were auth-only until 2026-08, and a Discovery's targets and results are the same kind of recon material). `POST /runs/:runId/adopt` is the one route with a CHAINED gate — `networkScan:write` AND `assets:write` — which is the whole permission design: running creates nothing, so a role may be allowed to find out what is on a range without being allowed to add it. `/preview-targets` is read-level on purpose (pure IP math plus one indexed read; gating it at write would block the wizard's target preview for a role allowed to look at Discoveries), and it plus `/runs/...` are declared BEFORE `/:id` so the literal paths aren't captured as ids. Schemas are SHAPE only — the semantic rules live in `networkScanService.validateScanInput`. `POST /:id/run` answers 202: the sweep takes minutes and the wizard watches the run row. Every route also resolves the caller's user id (`viewer(req)` — null for a bearer token, which therefore sees the PUBLIC set and owns nothing) and hands it to the service, which scopes the read; `assertMayEditScan` is the route-side owner-or-fullwrite check on PUT/DELETE, and `POST /:id/run` deliberately has no such check because running a shared Discovery is what sharing is for (business rule 34g). Tests: tests/integration/networkScans.test.ts
│   │       ├── notificationChannels.ts # NotificationChannel CRUD (Delivery tab) + per-channel Test send + VAPID generate (web_push). Gated automationManagement. Canonical mount /delivery-channels; deprecated alias /notification-channels. Backed by notificationChannelService + the channel senders.
│   │       ├── pushSubscriptions.ts  # Per-user Web Push subscription management + VAPID public-key handoff: GET /push-subscriptions/key (reads the web_push channel), POST/DELETE /push-subscriptions. Gated alerts:read (any viewer may opt in). Subscription owned by the session user; the web_push delivery channel routes to a user's endpoints. Since business rule 39 these are driven by `polarisPush.syncToPreference` reconciling a browser against `User.notificationPreference` at boot, not by an operator-facing on/off switch — there no longer is one.
│   │       ├── pwa.ts               # Web app manifest + home-screen icons for the MOBILE SPA. Mounted OUTSIDE /api/v1 in app.ts, before express.static. GET /manifest.webmanifest (built from branding, no-cache + weak ETag) and GET /icons/:file (strict ICON_SPECS allowlist → appIconService, ?v=<ver> immutable / bare max-age=300). UNAUTHENTICATED by design: a <link rel="manifest"> without crossorigin is fetched with credentials omitted, so a gated manifest 401s for everyone. Desktop pages carry no manifest link — the install identity is mobile-only.
│   │       ├── conflicts.ts         # Discovery conflict review routes — role-based visibility (visibleEntityTypes/canResolve) + thin accept/merge/reject handlers; the resolution engine lives in services/conflictResolutionService.ts

│   │       ├── groupMappings.ts     # IdP group → role + tags mapping CRUD, mounted at `/group-mappings` gated `users:fullwrite`. Thin over groupMappingService.
│   │       ├── userDashboard.ts     # Per-user dashboard layout GET/PUT at `/me/dashboard`.
│   │       ├── notificationPreference.ts # The caller's OWN alert delivery preference at `GET|PUT /me/notification-preference` (`email` | `push` | `any`). The third `/me/*` route — strictly per-caller, gated `alerts:read` on BOTH verbs (the push-subscription gate: choosing a delivery method is not an alert-management privilege). GET also returns `options` (value+label) so the desktop account menu and the mobile More tab render the server's vocabulary instead of each hardcoding labels. Thin over notificationPreferenceService; business rule 39.
│   │       ├── userTimezone.ts      # The caller's OWN display timezone at `GET|PUT /me/timezone` plus `POST /me/timezone/detected`. The `/me/table-tabs` sibling and deliberately NOT the `/me/notification-preference` one: it carries NO `requirePermission` at all, because what zone a timestamp is drawn in changes nothing about which data an account can reach, and gating it on any function key would leave some legitimate signed-in user unable to fix their own clock. GET returns `{timezone, serverTimezone, options}` — `serverTimezone` so the picker can say what `auto` will mean in an EMAIL, `options` so both clients render one server-supplied zone list. The PUT's Zod schema is STRICT (a zone this build can't format in is a 400) where the service's read-side normalizer is lenient. `POST /detected` is separate from the PUT on purpose: a client reporting where it is must never be able to overwrite a choice the operator made deliberately. Thin over userTimezoneService.
│   │       ├── tableTabs.ts         # Per-user list-page tabs GET/PUT at `/me/table-tabs?scope=assets` (the /me/dashboard sibling — strictly per-caller, no Event audit). Both verbs need only READ on the scope's function key: a tab is the operator's own view of data they can already see.
│   │       ├── savedDashboards.ts   # Saved dashboards CRUD at `/saved-dashboards` (Dashboard page → Dashboards ▾). Mounted TWICE — on the main router and on the Dash wallboard listener, which is session-less and GET-only, so a wallboard can load a published dashboard and structurally cannot save one. `savedDashboards:read` floor lives INSIDE the route file so both mounts share it; `write` is checked per request when `visibility:"public"` (publishing reaches every operator and the wallboard), `fullwrite` to delete someone else's. `GET /:id` is declared LAST and answers 404 — not 403 — for a row the caller can't see. Thin over savedDashboardService.
│   │       ├── savedFilters.ts      # Saved table-filter presets CRUD at `/saved-filters` (Assets page → Filters ▾). Gate resolved PER REQUEST from the body/query `scope` (savedFilterService.SAVED_FILTER_SCOPES maps scope → an existing function key), not at the mount: read for own/private, `write` to publish a public preset, `fullwrite` to delete someone else's. Thin over savedFilterService.
│   │       ├── agents.ts            # Polaris Agent runtime: enroll (public) / samples / config / heartbeat / system-info (bearer) / binary download (public, cert-pinned).
│   │       ├── agentsWs.ts          # Polaris Agent outbound WebSocket upgrade (bearer via Sec-WebSocket-Protocol).
│   │       ├── manufacturerAliases.ts # Admin CRUD for the manufacturer alias map (Fortinet, Inc. → Fortinet, etc.)
│   │       ├── assetTypes.ts          # CRUD for the operator-extensible AssetTypeDef registry, plus the device-type MATCHING surface. Mounted at `/asset-types` BEFORE `/assets` so Express picks the registry endpoint instead of treating "types" as an asset id. Reads gated by `assets=read`; writes by `assets=write` (admin + assetsadmin). Built-ins seeded by migration are `isProtected=true` and reject rename/delete — but NOT a rules edit (`isProtected` guards identity, not matching), so `PUT /:id` refuses a name/label/description change on one while accepting `matchRules` / `matchContexts` / `matchPriority`. Rename is transactional — every Asset row holding the old name is rewritten in the same `$transaction` as the registry update. Three matching routes, all declared BEFORE `/:id`: `GET /match-schema` (the field / operator / context vocabulary + `AUTHORITATIVE_TYPE_SOURCES`, so the card renders the server's list rather than a copy — the `/assets/pin-filter-schema` precedent), `POST /match-preview` (read-level dry run over assets currently typed `other`; an optional `draft` body previews an UNSAVED edit by substituting it into the live registry, since a draft judged alone over-reports every device a higher-priority type would have claimed first), and `POST /match-apply` (`assets=write`, the retroactive step, audited as `asset_type.rules_applied`). Body schemas here are SHAPE only — regex compilation, clause count and value length live in `validateMatchRules`, because the seed and preview paths reach the service without passing the route.
│   │       ├── mibs.ts              # MIB Database CRUD + Browse + MIB-aware Walk. Mounted at `/server-settings/mibs` BEFORE the rest of /server-settings so its per-route guards (admin OR assets-admin on reads, admin-only on writes) take precedence over the blanket `requireAdmin` on the rest of /server-settings. Carries the `/structure` (parsed object tree) and `/walk` (decoded MIB-aware SNMP walk) endpoints alongside the existing list/get/upload/delete/profile-status/facets routes that moved here from serverSettings.ts.
│   │       └── serverSettings.ts    # HTTPS, branding, backup/restore
│   ├── (services/ and jobs/ — see src-services-*.md and src-jobs.md)
```
