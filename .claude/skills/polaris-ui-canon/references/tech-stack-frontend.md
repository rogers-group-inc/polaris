## DOM screenshots (html-to-image)

html-to-image (bundled under `public/js/vendor/`) — SVG-foreignObject capture of the asset-details active tab at a canonical 1100px width (independent of the operator's slide-over size), driven by a section-picker modal (per-section include/exclude via `data-shot-section` wrappers, hidden-interface reveal, temporary chart-range swap with guaranteed restore); CSP `connect-src` whitelists the Google Fonts hosts so webfonts embed into the PNG. ## Graph layout (Cytoscape.js column solver, dagre fallback)

Cytoscape.js for the Device Map topology modal; nodes positioned by a deterministic Dijkstra-weighted **column solver** (`computeTopologyColumns` in `topology-render.js`). Column **anchors** (FortiGate + switches + branch APs — mesh roots / bridged-switch parents) land on even columns by weighted depth; **leaves** (wired endpoints, wireless stations, and *terminal* managed APs) hang in the odd column right of their parent. Rows come in two passes: a **nearest-free-slot packing** pass over the anchors (first anchor child continues the parent's row so chains stay flat; every other anchor scans downward from just below its parent's row for the first lane where its whole footprint fits — its own cell, the spine chain that inherits its lane into later columns, and each chain member's planned AP block — so rows pack tight near the spine and spread only where subtrees congest, instead of every subtree pre-claiming a disjoint band), then a leaf pass that slides each parent's leaves as one **contiguous window** starting at the parent's row (one below it when its spine continues), blocks ordered by parent row — so a switch's APs line up directly beneath it, grouped together, never split apart or interleaved by another switch's APs. **Location codes** (`a:`/`b:`/`f:`/`r:`/`jb:` = area/building/floor/room/junction-box, parsed from device descriptions/notes by `src/utils/locationCodes.ts`) additionally cluster non-spine sibling anchors sharing an area (then building, then floor, then room, then junction box — `stableBucketByTiers`; fallback-exile roots and each parent's leaf block are ordered through the same tier chain, so room/jb co-members take contiguous lanes and their hulls come out as tight bands) into adjacent row bands, and draw **grouping hulls** as synthetic bottom-layer Cytoscape nodes (nested rounded rectangles color-coded per level — area rose > building sky-blue > floor violet dashed > room green > jb amber dashed, fitted inside-out with a sibling-separation sweep so shapes never overlap; plain nodes, not compound parents, so `cy.png()` screenshots capture them); when any device carries `b:` or `f:`, the modal offers a two-row drill-down switcher of **building views** (Flat default + one chip per building; the active building's "All" + **floor view** chips — per (area, building, floor) — appear in a second row) with dashed **portal** stubs where a member's edge crosses views (tap → jump; `computeFloorViews` / `partitionElementsForFloor`). Location-coded sites additionally get the **quotient layout** (`computeGroupedLayout`): each top-level group (area, else building; uncoded nodes pooled) is compacted to its own subtree size via rank-compression of the flat solver's coordinates, and the group boxes are shelf-packed left-to-right in entry-depth order with a height budget of the tallest box — flat solver semantics inside every box, no dead width between boxes. dagre + cytoscape-dagre (bundled under `public/js/vendor/`) remain the fallback when there's no FortiGate root

**The graph's palette is APP-themed, and its stylesheet is not reactive.**
`topologyStylesheet(family)` in `topology-render.js` takes a theme FAMILY — `"dark"` or
`"light"`, never a theme id — and is evaluated once per render. Two rules follow. First,
the family must be the one the *canvas* is painted in: `.topology-graph` paints
`--color-bg-secondary`, an app-themed token, so the desktop modal derives it from
`isLightTheme()` (`appThemeFamily()` in `map.js`). It used to take the per-user **basemap**
preference on the theory that one toolbar toggle should drive the map and the modal
together — but the topology modal has no basemap, so a nightfall operator who preferred
light OpenStreetMap tiles got `#1a1a1a` node labels on a `#0d0d1a` pane. The basemap toggle
now leaves the modal alone. Second, because nothing re-reads the stylesheet, any palette
input that changes under an OPEN modal has to re-render it: `map.js`'s `data-theme`
observer calls `repaintOpenTopology()`, and the phone's topology tab does the same.
`topologyStylesheet` also resolves anything that isn't a family from the document's own
`data-theme` rather than falling through to the light branch, so a caller that passes an id
degrades to the right palette instead of the opposite one.
