## Mapping (Leaflet + OpenStreetMap tiles)

Every geographic surface draws its basemap from **one host, one URL**: `https://tile.openstreetmap.org/{z}/{x}/{y}.png`. The OSM tile usage policy permits that URL and no other — the older `{s}` a/b/c subdomain form spreads a single viewport across three hosts instead of one multiplexed HTTP/2 connection, and OSM's operators read it as a policy violation and answer with the "Access blocked" tile image in place of the map. Polaris shipped the subdomain form until 2026-09-15, when a personal install's maps came back blocked while the Rogers Group production install — same code, different viewer egress IP — kept rendering.

Four files declare the URL and they move together: `public/js/map.js → applyBasemapTheme()` (Device Map), `public/js/mobile/map-tab.js → applyBasemapTheme()` (phone Map tab), and `public/js/widgets/deviceMap.js → applyBasemap()` + `public/js/widgets/siteMap.js → applyBasemap()` (the two dashboard widgets). `src/utils/securityHeaders.ts → buildHelmetOptions()` whitelists exactly that host in CSP `imgSrc`, deliberately **without** a `*.tile.openstreetmap.org` wildcard, so a reintroduced subdomain form fails loudly at the CSP instead of quietly earning another block.

**The gate is the `Referer` header, not the URL and not the IP.** Measured 2026-09-15 with curl from the corporate network: the same tile URL returns a real tile when a `Referer` is sent (on the `a.` subdomain too) and the "Access blocked" image, with an `x-blocked: Access denied` response header, when it is not — OSM blocks every referer-less request outright. Polaris does its part: `src/utils/securityHeaders.ts → buildHelmetOptions()` sends `Referrer-Policy: strict-origin-when-cross-origin` (on OSM's accepted list), every layer renders the `© OpenStreetMap contributors` attribution, and `public/sw.js` registers no fetch handler, so the PWA never re-requests a tile the browser has cached. So when an install on current code still shows blocked tiles, the Referer is being dropped between browser and OSM — almost always a **reverse proxy in front of Polaris appending its own `Referrer-Policy: same-origin` / `no-referrer`** (SWAG's `ssl.conf` hardening block, Nginx Proxy Manager advanced config, Traefik/Caddy/Cloudflare header rules; browsers apply the *last* Referrer-Policy value they receive, so the edge wins), less often a browser privacy extension, rarely an IP-level block. That is why `deploy/nginx/polaris.conf` and `polaris.conf.template` carry a comment forbidding a Referrer-Policy at the edge, and why `docs/INSTALL.md` has the operator-facing section "Map tiles come back as Access blocked". Diagnose with DevTools → Network → a tile request's `Referer` header, or `curl -sI <polaris>/login | grep -i referrer-policy` (one line, `strict-origin-when-cross-origin`). **Never** by pasting a tile URL into the address bar: an address-bar navigation carries no Referer and shows the blocked image on every network, including ones where the map works — the home install's first diagnosis went wrong on exactly that.

Dark mode is the same tiles under a CSS filter (`.polaris-basemap-dark` in `public/css/styles.css`, `.sitemap-dark` for the widget flavor), never a second tile source: CARTO's Dark Matter served the dark half until CARTO began requiring an API key on its basemap CDN. That history is why the rule is *one unkeyed host* — moving to a keyed provider, or making the tile URL an operator setting (offered and deferred 2026-09-15), is a design change across all four files plus the CSP, not a drop-in swap.

## DOM screenshots (html-to-image)

html-to-image (bundled under `public/js/vendor/`) — SVG-foreignObject capture of the asset-details active tab at a canonical 1100px width (independent of the operator's slide-over size), driven by a section-picker modal (per-section include/exclude via `data-shot-section` wrappers, hidden-interface reveal, temporary chart-range swap with guaranteed restore); CSP `connect-src` whitelists the Google Fonts hosts so webfonts embed into the PNG. The same capture backs the header's PDF button (`_saveCaptureAsPdf`, paginated letter-portrait via jsPDF). The Events tab swaps Screenshot + PDF for an asset-scoped CSV/PDF Export dropdown instead. The mobile SPA reuses html-to-image for the asset sheet's header Screenshot button (natural-width capture, share-sheet → clipboard → download delivery)

The per-table camera buttons use the same library (`_screenshotTableEl`), capturing the live `<table>` element — never its scroll wrapper, which would clip everything below the fold — at its current rendered width, on the backdrop of the first ancestor that actually paints, composed under a label + hostname title strip. A synthetic canvas that re-drew each cell's TEXT held that job until 2026-09-21 and survives as the fallback (`_screenshotTableElText`); the two paths and the `data-shot-text` / `data-shot-color` contract that only the fallback reads are in polaris-ui-canon → canon-tables-lists.md.

## Graph layout (Cytoscape.js column solver, dagre fallback)

Cytoscape.js for the Device Map topology modal; nodes positioned by a deterministic Dijkstra-weighted **column solver** (`computeTopologyColumns` in `topology-render.js`). Column **anchors** (FortiGate + switches + branch APs — mesh roots / bridged-switch parents) land on even columns by weighted depth; **leaves** (wired endpoints, wireless stations, and *terminal* managed APs) hang in the odd column right of their parent. Rows come in two passes: a **nearest-free-slot packing** pass over the anchors (first anchor child continues the parent's row so chains stay flat; every other anchor scans downward from just below its parent's row for the first lane where its whole footprint fits — its own cell, the spine chain that inherits its lane into later columns, each chain member's planned AP block, the **spine-edge cell** (leaf column, own row) every continuing member's links leave through, and the **corridor cells** a child four or more columns from its parent runs through along its own row — so rows pack tight near the spine and spread only where subtrees congest, instead of every subtree pre-claiming a disjoint band), then a leaf pass that slides each parent's leaves as one **contiguous window** starting at the parent's row (one below it when its spine continues), blocks ordered by parent row — so a switch's APs line up directly beneath it, grouped together, never split apart or interleaved by another switch's APs. **Fan-out edges** — any edge between two nodes two-plus columns apart on different rows (a switch to its non-spine child switches, a mesh root to its leaves) — are drawn orthogonally, not diagonally: an L hugging the shallow end — a turn in the gutter HALF a column along, then along the deep end's row through the leaf column. The turn sat at 1.5 columns until 2026-10-16, which ran the edge along the shallow row beside the switch's straight spine link, so two child switches read as hanging off one port; at 0.5 the spine's port label sits right of the L. Where any bent or shared link's label goes is `refreshBentEdgeLabels` (below), not Cytoscape's midpoint. The leaf pass dodges the deep-row run through the leaf column (`edgeLaneAt` → `fanOutLaneAt`, which answers the deep row for every crossed column), and the anchor footprint reserves the corridor cells past it; `markFanOutEdges(cy, columns, {colSpacing, orientation})` stamps the matching `taxi` geometry (`isFanOut` / `fanOutDir` / signed `fanOutTurn`, measured from the shallow end) after the preset layout on both surfaces — `orientation` is `"horizontal"` on the desktop and `"vertical"` on the phone, which transposes the grid. Before this, a sibling's spine edge sliced through the row an earlier sibling's last AP was planned for and the leaf pass slid the whole AP block rows away from its switch. A **mesh / bridge leaf's** only bogus edge is the parent → leaf uplink (the same test `buildTopologyElements` drops by); its own downstream edges — a bridged switch's wired FortiAP, a switch chained behind it — stay, and physical verification flows through mesh and bridge edges, so nothing behind an AP is orphaned into the stray rows or exiled as a FortiLink fallback. **Location codes** (`a:`/`b:`/`f:`/`r:`/`jb:` = area/building/floor/room/junction-box, parsed from device descriptions/notes by `src/utils/locationCodes.ts`) additionally cluster non-spine sibling anchors sharing an area (then building, then floor, then room, then junction box — `stableBucketByTiers`; fallback-exile roots and each parent's leaf block are ordered through the same tier chain, so room/jb co-members take contiguous lanes and their hulls come out as tight bands) into adjacent row bands, and draw **grouping hulls** as synthetic bottom-layer Cytoscape nodes (nested rounded rectangles color-coded per level — area rose > building sky-blue > floor violet dashed > room green > jb amber dashed, fitted inside-out with a sibling-separation sweep so shapes never overlap; plain nodes, not compound parents, so `cy.png()` screenshots capture them); when any device carries `b:` or `f:`, the modal offers a one-row-per-level drill-down switcher (**Base** — the whole site, view key `flat` — alone on top; then the **area view** chips plus any area-less building, or just the **building views** on a site with no areas; under a selected area its buildings; under a selected building its **floor view** chips, per (area, building, floor); every chip on the selected path lit — `viewSwitcherRows`) with dashed **portal** stubs where a member's edge crosses views (tap → jump; `computeFloorViews` / `partitionElementsForFloor`) — the FortiGate itself appears only in Base and its own tagged views, a dashed `isRootPortal` stub (`→ Base: <FG>`) standing in for it, and rooting the solver, everywhere else. **Operator-drawn connection lines** (`public/js/topology-edge-editor.js` → `attach()`, desktop modal only): dragging a line adds a selected bend, clicking it shows bend dots + an end-point ring per device that slides around the device outline, Delete removes the selected point; a drawn line is `customPath` and the inter-group router leaves it alone. The router (`routeInterGroupEdges`) never places a bend inside either end device (`_nodeClearance`: outer radius + 6 px): Cytoscape cannot find where a segment starting inside a node leaves it, marks the edge `badLine` and draws NOTHING, leaving only its selection handles. A run fanned a few px off its target's row therefore steps back to that row just before the target instead of jogging inside it (pinned by `tests/unit/topologyRouteBendClearance.test.ts`). Its geometry is saved in the view's layout blob as `edgepath:` entries keyed by kind + source + target (element ids are payload indices), so Save / Reset need nothing of their own; the handles are `noExport`, which `graph-export.js → readScene` skips. **The modal opens view-only**: a dashboard-style Edit button (pencil / Done check, `#topology-edit`) switches on dragging, line editing and the edit-only corner tools — Grid, Snap devices, Snap line points, and Save / Reset / Undo / Redo in a column under Edit (map.js → `_ensureTopologyCornerTools` / `_applyTopologyEditMode`; the full inventory is in polaris-change-impact → file-map/public-2.md). Lines are always straight between their points (a curved Photoshop-wing mode was built and removed 2026-10-26). **Two Cytoscape traps** this surface hit, both invisible to headless unit tests: (1) never snap a GRABBED node's position inside its `position` handler — Cytoscape moves a grabbed node by the pointer delta since the last event, so per-event snapping discards every sub-half-cell move and the node freezes; accumulate the raw drag position and snap that (the editor's `dragRaw`); (2) a press on an EDGE that code turns into a drag is still a CLICK to Cytoscape on release (edges are not grabbable), so `selectionType: "single"` selects what is under the pointer and drops the rest — re-assert selection in a `setTimeout(0)` after `tapend`. Verify drag work with the CDP mouse harness in small steps, logging every step. Location-coded sites additionally get the **quotient layout** (`computeGroupedLayout`): each top-level group (area, else building; uncoded nodes pooled) is compacted to its own subtree size via rank-compression of the flat solver's coordinates, and the group boxes are shelf-packed left-to-right in entry-depth order with a height budget of the tallest box — flat solver semantics inside every box, no dead width between boxes. dagre + cytoscape-dagre (bundled under `public/js/vendor/`) remain the fallback when there's no FortiGate root

**The graph's palette is APP-themed, and its stylesheet is not reactive.**
`topologyStylesheet(family)` in `topology-render.js` takes a theme FAMILY — `"dark"` or
`"light"`, never a theme id — and is evaluated once per render. Two rules follow. First,
the family must be the one the *canvas* is painted in: `.topology-graph` paints
`--color-bg-secondary`, an app-themed token, so the desktop modal derives it from
`isLightTheme()` (`appThemeFamily()` in `map.js`). It used to take the per-user **basemap**
preference on the theory that one toolbar toggle should drive the map and the modal
together — but the topology modal has no basemap, so a nightfall operator who preferred
light OpenStreetMap tiles got `#1a1a1a` node labels on a `#0d0d1a` pane. The basemap toggle
now leaves the modal alone. Second, because nothing re-reads the stylesheet, any palette
input that changes under an OPEN modal has to re-render it: `map.js`'s `data-theme`
observer calls `repaintOpenTopology()`, and the phone's topology tab does the same.
`topologyStylesheet` also resolves anything that isn't a family from the document's own
`data-theme` rather than falling through to the light branch, so a caller that passes an id
degrades to the right palette instead of the opposite one.

**Link and location-box colours are per family** (since 2026-10-16). `EDGE_COLORS.dark` is
the original 300/400 pastel set; on the daylight grounds those measured 1.3–2.4:1 (cyan
wireless, amber LLDP and the sky-blue building box all but vanished), so `EDGE_COLORS.light`
and `LOC_GROUP_KINDS[kind].colorLight` step each hue to its 600/700 shade — ≥ 3.2:1 on
morning's `#e8d4ad`, ≥ 3.8:1 on noon's `#eae8e5` (WCAG non-text 3:1). Same hue per kind in
both families. `locGroupColor(kind, family?)` and `topologyLegendSpec(family?)` resolve the
family like the stylesheet does (`paletteFamily`, omitted → the document's), so the hulls,
their tooltip and the legend follow the canvas; `map.js`'s `data-theme` observer also
re-renders the legend body, which is otherwise filled once. Node health fills are the
monitor-state palette and are NOT remapped. `topologyColumns.test.ts` holds the stylesheet's
line colours equal to the legend's in both families — add a link kind to both or it fails.

**Port labels on bent and shared links** (operator rule, 2026-10-16). Cytoscape puts an
edge label at the path midpoint — on a taxi / routed link, a middle leg far from both
devices. `refreshBentEdgeLabels(cy)` in `topology-render.js` re-places them: one bend →
halfway along the second leg; two or more → halfway along the first leg plus a copy halfway
along the last; and never on a stretch another link runs along (within 3 px, parallel) — the
label takes the middle of the longest unshared run (≥ 24 px) of its leg, else the next leg
inward, else it is hidden (`label: ""`). Straight links keep the midpoint unless it is shared;
curved beziers are skipped. It writes per-edge bypasses (`text-margin-x/y` from the midpoint
— Cytoscape adds the margin before rotating, about the shifted point — an explicit
`text-rotation`, and `target-label` + `target-text-offset` for the copy) and keeps a
signature in `data(_bentLabel)` so an unchanged edge is never re-styled. Overlap lookup is an
axis-line bucket index, not a pass per edge pair: the pass runs once per frame while a node
is dragged (`wireBentEdgeLabels` — `position` + `layoutstop`, rAF-coalesced; both surfaces
wire it). Geometry changed by style alone must call it: the EXPORTED `routeInterGroupEdges`
does, and so does map.js's Locations-off branch that strips the routed bypasses. The PDF /
Visio export reads the shifted main label (it applies text-margin, printed horizontal) and
does not draw the target-label copy. Pinned by `tests/unit/topologyBentEdgeLabels.test.ts`.

**The side panel follows the boxes.** With the Locations chip on (`topoState.hasLocationCodes
&& _readShowLocations()`), `renderTopologyInfo` lists FortiSwitches and FortiAPs in the
boxes' nesting order — area › building › floor › room › junction box, numeric-aware names,
unlocated devices last — under one `li.topology-loc-group` heading per group
(`_sortByLocationGroups` / `_topologyLocationHeadings` in `map.js`); the chip re-renders the
panel. Chip off → the payload's order, unchanged.
