The 2FA row (`wireTotpState` → `_totpState`, `_totpMenuItem`, `_openTotpSelf`, and `refreshTotpState` — exposed because /users.html hosts the same flow off its own row menu and the cached row would otherwise still read "Set up" on the page where it was just enabled) is push enrollment’s permission-mismatch fix applied again: `/auth/totp/*` is self-service for any logged-in local account, but the only UI was on the admin-gated /users.html. - **Per-user panel lock** (`app.js`) — a lock button sits left of the X on every modal and slide-over. Two app-wide switches (one for all modals, one for all slide-overs), saved per user in `localStorage` under `polaris.panellock.<username>`. **Locked** → a backdrop/off-panel click does NOT dismiss the panel (the X gets the same escalating glow + radial bloom as the modal X via the shared `flashModalCloseBtn`); **unlocked** (default) → an off-click closes it. The X and Escape always close regardless. Modals route through `openModal` (handled inline); slide-overs each wire their own backdrop-close, so a capture-phase document listener blocks that close when locked instead of editing every panel, and a `MutationObserver` injects the lock button into any newly-created panel (so new slide-overs get one for free). A hover tooltip explains the current state.

- Device Map page has an **Edit regions** toolbar button (admin/networkadmin only — gated by `canManageNetworks()` on the client; backend guard is the source of truth). The default map view never renders region polygons — they appear only after entering edit mode. Edit mode mounts `L.Control.Draw` (vendored leaflet-draw 1.0.4) for drawing new polygons, overlays existing regions on a dedicated `L.featureGroup`, and binds permanent name labels at each polygon's centroid. **Draw new** prompts for a name via `openModal()` and posts to `POST /map/regions`. **Click an existing polygon** opens a popup with **Rename** / **Change color** / **Send to Bottom Layer** / **Delete** actions. **Send to Bottom Layer** calls `poly.bringToBack()` so a region nested inside another (overlapping polygons where the outer one was drawn later and visually obscures the inner one) can be clicked through to — per-session only, the saved-on-server order doesn't change. **Drag a vertex** (or midpoint) reshapes the polygon in-memory — vertex editing is always on per polygon in edit mode (no separate Edit toolbar round-trip); every drag fires `editvertex` and marks the polygon dirty without issuing a PUT. **Right-click drag** pans the map (always on; context menu is suppressed inside the map container). Useful while drawing a polygon, since left-click is captured for vertex placement. **Save Regions** commits every dirty polygon via SEQUENTIAL PUTs (they serialize on the server's region-blob advisory lock anyway — parallel requests just parked N connections on it), then exits edit mode; per-polygon failures alert the operator and leave edit mode open so the operator can retry or discard. Every successful save — including a click with zero dirty polygons — then fires `POST /map/regions/reconcile` (`reviewRegionTags` in map.js): the fleet-wide region-tag review that re-adds members, strips provenance-tracked drift, and removes region tags from pinned FortiGates no longer inside the named polygon (the gate that MOVED case, which no polygon PUT would otherwise cover). The review is non-fatal — a failure downgrades to a toast, since the polygon saves already landed — and its summary is appended to the toolbar status line. **Discard Changes** reverts every dirty polygon to its loaded shape via `setLatLngs` (with an editing-handle refresh) and exits edit mode — rename/delete/draw-new actions taken during the session are NOT in the dirty bucket because they hit the server immediately on click, so Discard can't undo them. The save/discard buttons sit alongside the Edit-regions button in the toolbar; visibility flips via `setEditModeButtons` so only the relevant set is shown for the current mode. The draw plugin's CSS sprite assets live alongside the existing Leaflet marker images at [public/css/vendor/leaflet/images/](public/css/vendor/leaflet/images/) (`spritesheet.png`, `spritesheet-2x.png`, `spritesheet.svg`). Each region maps to a `region:<name>` tag stamped by the backend reconciler on every enclosed firewall asset, cascaded to its managed FortiSwitches / FortiAPs (`fortinetTopology.controllerFortigate`), and stamped on the `Subnet` rows those gates serve plus the assets addressed out of them — see "Map Regions" under the API surface.
- Asset list shows a five-state Status pill (**Up** green / **Missed** amber / **Pending** blue / **Down** red / **Unmonitored** grey). For admin/assetsadmin the pill is **clickable** — single click toggles `monitored`; the server then recomputes `monitorOverride` (true when the new monitored value diverges from the discovering integration's per-class `addAsMonitored`, false when they match — including when the operator's click brings them back into agreement). On the asset details slide-in **System tab**, an **Asset Override** badge (`_assetOverrideBadge` in `public/js/assets.js`) renders next to the Status pill when `monitorOverride === true` so the operator can see at a glance which assets have been pinned away from the integration's auto-monitor default. The Type column pill is also clickable for admin/assetsadmin and opens a dropdown of the live `AssetTypeDef` registry for inline reclassification (built from `ASSET_TYPE_OPTIONS`, so operator-added custom types are offered and a type retired from the registry is not — the asset's OWN type is always kept as an option, so opening the menu can never hide what the row currently is). The bulk-action toolbar (always visible, idle-styled and disabled until rows are selected) is built from three dropdowns and three labelled buttons: **Type ▾** / **State ▾** loop a per-asset `PUT /assets/:id` for the chosen `assetType` / `status`; **Monitoring ▾** (Enable / Disable) hits `POST /assets/bulk-monitor`; **Edit** opens the single-asset edit modal (`openEditModal`) for the selected row — it stays visible but greys out unless exactly one asset is selected, and it replaced the former tags-only bulk **Edit Tags** modal (tags are now edited per-asset in that modal, or fleet-wide via `Tag.criteria` auto-assignment); **Quarantine selected** / **Release Quarantine** route through the dedicated `/assets/bulk-quarantine` and `/assets/bulk-quarantine/release` endpoints; **Delete selected** posts to `DELETE /assets`; **Compare** overlays the telemetry of the selected assets and, needing two to overlay, stays VISIBLE and greys out below two rather than appearing only once the right number is ticked (**Merge** is the exception that still hides — it is pairwise AND admin-only). The State menu is populated from the `ASSET_STATUS_LABELS` map in `public/js/assets.js`; the Type menu reads `ASSET_TYPE_OPTIONS` — the registry list — via `_renderBulkTypeMenu()`, which is called BOTH at wire time and again from `_loadAssetTypeOptions()` once `GET /asset-types` answers, because the bulk bar is wired before that fetch resolves (without the second call the menu carried the built-in seed forever and a custom type was unreachable from the bulk bar); `quarantined` is intentionally not a State option (the regular asset PUT rejects that status — quarantine has its own flow). The Acquired date is intentionally omitted from the list — it lives only on the asset details slide-in (General tab) to keep the row narrow.
- The bulk-action toolbar also carries a **Compare** button (shown when 2+ rows are selected; no `data-manage-assets` gate — comparing telemetry is read-only). It opens a **metric picker modal** (`openCompareModal` in `public/js/assets-compare.js`) — Response time / CPU % / Memory % / Storage % / a single combined **Interface throughput & errors** toggle (which fans out internally to the `ifThroughput` + `ifErrors` sub-metrics, one chart each), a layout choice (one chart per metric with assets overlaid, vs overlaid one-chart-per-unit), and — when the interface toggle is on — an interface-name picker built from the union of `system-info` interfaces across the selected assets. The picker has **Select all / Deselect all** (deselecting all is allowed — interface charts just don't render; only blocked when interfaces is the sole metric), lists each interface's assets with their **alias / aggregate annotation in parentheses** (`alias: …` / `member of <agg>` / `VLAN on <parent>`, from the already-fetched system-info), and shows a per-asset **usage preview** (recent 1h average throughput, or "down" / "no data") so the operator can tell which interfaces carry traffic — auto-loaded when ≤60 (asset × interface) readings, button-gated above that to stay cheap at fleet scale ("N of M assets" counts mark how shared each name is). **Compare** then opens a slide-over (`openComparePanel`) that overlays the selected assets' telemetry on SVG charts built with the canonical chart helpers (`_renderCompareChart` reuses `_chartTimeBounds` / `_chartClip*` / `_dateChangeMarkers` / `_observeChartResize` / `_wireChartTooltip`), with a 1h/12h/24h/7d/30d/Custom range bar, a per-chart legend, and footer **Screenshot** (html-to-image → clipboard at the canonical 1100px width) + **Export PDF** (`trackedPdfExport` → one chart image per block via html-to-image). Selection is soft-capped at 10 assets for readability. Fetches per (asset × metric [× interface]) reuse the existing `monitorHistory` / `telemetryHistory` / `interfaceHistory` / `storageHistory` endpoints — no backend changes. Storage % uses the asset's largest mountpoint. Mock data for exercising it: `npm run mock:compare` (`prisma/mock-compare.ts`).

- Asset details slide-in **System** tab status block: just under the Status pill is a **last-hour intermittency bar** — one cell per probe sample over the past hour, colored by the resolved monitor state at that point (green=up / amber=**Missed** / **blue**=recovering / red=down — blue `rgba(2,136,209,·)`, the SAME value the response-time chart directly below uses for the same state; it was the magenta-leaning purple 400 until 2026-08-29, chosen when that chart's series was still the theme accent, and it sat one shade from the muted lavender that means maintenance). Each cell's tooltip carries the RUNNING missed count and the direction it moved (`Missed 2 (+1)` / `Received — 1 missed outstanding (−1)`), because "Missed" on four cells in a row does not say whether the device is climbing toward Down or paying its way back out. `_intermittencyStates` — a one-line delegate to the shared `PolarisMonitorStates.replay` in `public/js/monitor-states.js`, which the response-time chart below the bar and the phone's copy of that chart read too — replays the leaky bucket forward over the samples client-side using the COVERING AUTOMATION's counts from `/effective-monitor-settings`' `downDetection` block (`missedPolls`, and `recoveryPolls` for the climb — business rule 36, no longer the settings tiers' `failureThreshold`), so a brief blip shows up as one yellow cell, a true outage as a sustained red run, and the recovery that follows it as a BLUE run until the automation's reset count of answers has landed. Failed probes stay yellow/red even mid-recovery. `passive` (no automation covers the device) means no cell may go red. Hovering a cell shows the timestamp + status. Hidden on unmonitored assets.

- Asset edit modal is tab-based (General + Monitoring). The details modal has three tabs by default (General + System + **Sources**) and adds a fourth **SNMP Walk** tab for admins (admin-only on both the frontend and the backend) — and only when at least one monitoring stream actually resolves to SNMP for the asset: `_assetUsesSnmpPolling` checks the eight resolved `*Polling` fields from `/effective-monitor-settings` (prefetched in the view modal's parallel auxResults pass so the tab never flashes-then-vanishes, admin-only fetch) plus the per-asset `customWidgetPolling`; a failed fetch fails open so a transient error can't hide the tab. The backend route stays admin-gated but method-agnostic (an admin can still walk via the API). Controls: a **MIB** dropdown (optional — groups Standard MIBs and Uploaded MIBs), a **Base OID / Object name** input that switches label and validation based on the selected MIB, an SNMP credential picker (any stored SNMP credential), and a Max-rows input (default 500, capped at 5,000). **Standard MIBs** (System, IF-MIB, IF-MIB Extended, HOST-RESOURCES-MIB, ENTITY-MIB, ENTITY-SENSOR-MIB, LLDP-MIB) render the same browse tree + object-name input as uploaded MIBs, backed by the bundled text files under [src/services/stdMibs/](src/services/stdMibs/) (see `stdMibLibrary.ts`). Tree fetcher is selected per id-prefix in `_loadAndRenderMibTree`: `std:*` calls `api.serverSettings.getStdMibStructure(key)`, UUID calls `getMibStructure(id)`. The walk button likewise dispatches to `walkStdMib` for std ids and `walkMib` for uploaded UUIDs. **Uploaded MIBs** (from the MIB Database in Server Settings) switch the input to an object name field, render a **browse tree** beneath the buttons row (Tables + Scalars / Other sections from `GET /server-settings/mibs/:id/structure`, cached per mibId in `_snmpMibStructureCache`) where clicking a symbol fills the Object name input + highlights the row without auto-walking (typing in the input still works as the source of truth), and use the MIB-aware walk (`POST /server-settings/mibs/:id/walk` with `{ assetId, credentialId, objectName, maxRows }`) — results render decoded: `kind: "table"` as a 2D grid with column headers and index column (decoded enum labels with raw value in tooltip on hover), `kind: "scalars"` as OID / Symbol / Value rows (decoded value with raw in parentheses). A yellow banner fires when `decodedCount < rowCount / 2` (MIB doesn't match the asset's manufacturer). **No MIB** (default) uses raw numeric walk with manual OID entry. Abort is available for every walk kind (the MIB-aware API helpers accept an abort signal too), and a 60-second client-enforced deadline renders as a live countdown next to the Walk button — at zero the request is aborted and the tab reports "Walk timed out after 60s." (the server-side walk still runs to completion; abort only abandons the response). Walks acquire the per-host SNMP gate with a 50s wait budget (`SNMP_WALK_GATE_WAIT_MS`, vs. the collectors' 30s `POLARIS_SNMP_GATE_WAIT_TIMEOUT_MS` default) so a walk queued behind a monitoring poll on the same device gets the whole countdown window to start; a gate timeout is surfaced as a "device was busy" message since the walk never ran. Copy results produces TSV for tables and one-per-line `symbol = decoded (raw)` for scalars. MIB selection, OID/object name, and credential persist across tab open/close via module-level variables (`_snmpWalkLastMibId`, `_snmpWalkLastObjectName`, `_snmpWalkLastOid`, `_snmpWalkLastCredId`). Uploaded MIBs load lazily on first tab wire from `api.mibs.listMibs({})` and are cached in `_snmpMibCache`. Each walk is audited as an `asset.snmp_walk` Event. The Monitoring tab on the edit modal renders an editable type dropdown for every asset; integration-discovered assets (FMG/FortiGate-discovered firewalls and AD-discovered Windows/Linux hosts) get an extra option representing the integration default (e.g. "FortiManager: \<name\> (default)") plus a hint pointing operators to SNMP for small-branch FortiGates whose REST sensor endpoint 404s. The **System** details tab leads with the monitoring section — status pill, source, last RTT/poll/consecutive failures, and an SVG response-time chart (1h / 12h / 24h / 7d / 30d / Custom; failed probes render as red dots at 0 ms, the line fading into red across the outage — no more full-height failure lines; click-drag on any chart applies the selection as a custom window) plus a "Refresh" button for user-or-above (kicks off all three streams — response-time probe, telemetry, system-info — and the toast names exactly which streams refreshed and which failed, e.g. `Refresh partial (probe 12 ms · telemetry) — interfaces: FortiManager direct-mode API token not configured`) — then a horizontal divider, then a single combined CPU+Memory chart (both lines on a shared 0–100% y-axis with one hover tooltip naming both values) over 1h / 12h / 24h / 7d / 30d / Custom, a Temperatures section (current sensor table — hidden when the device exposes no sensors — with each sensor name clickable to open a per-sensor slide-over chart), an Interfaces table with a "Poll 1m" checkbox column + clickable interface name + **Native VLAN** + **Tagged VLANs** columns that render only when at least one row in the table actually carries port-VLAN data (managed FortiSwitches overlaid from the parent FortiGate's CMDB — see `AssetInterfaceSample.nativeVlan` / `taggedVlans` / `trunksAllVlans`); the Tagged cell collapses long lists past 6 entries to "first 6, +N more" with the full list in the cell tooltip, and renders a teal `all` pill for trunk-all ports. **Per-column sort + filter (TableSF), and no rows are hidden** (2026-08). Traffic-less interfaces and tunnels used to ship `display:none` behind a `▶ Show N inactive interfaces (no traffic)` expander; that whole mechanism is gone — "no counters yet" was a poor proxy for "not interesting" (an admin-shut port being hunted for, a link that just came up, a dead tunnel that should be up), and the expander was a bespoke control answering one question. The table now carries the same `TableSF` header controls every other Polaris list table does, over a flat **row model** built alongside the tree (`_ifaceEntry` / `_tunnelEntry` in `_buildInterfacesTableDOM`): text filters on Interface / IP / MAC / Neighbor, multi-select filters on Status / PoE / Addressing / Native VLAN / Tagged VLANs, sort-only (`data-sf-nofilter`) on Speed / In / Out / Errors. Each entry field is named for the column's existing `data-col-id` (`ifname`, `native-vlan`, `in`, …) because `setupColumnLayout` derives a column's persistence id from `data-sf-key` first — keeping them identical is what lets already-saved column widths / hidden columns / drag order keep applying. `ifname` is an ARRAY (`[alias, ifName]`) so an aliased port sorts by the label the operator reads and still matches its real ifName. Status, PoE and both VLAN columns get their options from what THIS device reported (`setColumnOptions` over the entries) — the VLAN pair through `_distinctVlanOptions` rather than `_distinctSorted`, because the latter's alphabetical order lists 100 and 1000 between 10 and 20 in a column whose every value is a number (non-numeric sentinels, i.e. the Tagged column's trunk-all `all`, sort last). Both VLAN columns are pickers rather than text boxes on purpose: a VLAN is an identifier out of a closed set the switch just reported, so there is nothing to type that isn't already offered — and a substring filter matched 100/110/210 when the operator typed 10. That is also why the Tagged column's row value is an **array** (`taggedVlanList`) instead of the joined display string: TableSF matches a multi-select selection against each element, which is what lets "Tagged VLANs: 30" select the ports carrying VLAN 30 out of a 40-VLAN trunk list. A trunk-all port carries the single `all` element and deliberately does NOT match a specific VLAN — the device enumerated none, and that matches what its cell renders. Stored string filters from before the columns became pickers are dropped on restore by `restoreFilterUI`'s shape check (a string left in place would filter by substring through a control that can't display or clear it), and a tunnel's unanswerable columns are null/"" rather than 0, so a tunnel never turns up under "PoE: fault" nor sorts as the slowest link. **Two render modes** (`renderBody`): with no sort and no filter it's the nested tree with its section headers exactly as before; the moment either is active it renders **flat** — no section headers, no indentation, no expand toggles (a row's position no longer implies parentage, and half a tree is worse than an honest list; a member port keeps its "Member" badge as the only remaining cue). Only the tbody is rewritten, so TableSF's rebuilt header row and `applyTableLayout`'s widths/handles survive. The header is **frozen** — the wrapper carries `.table-wrapper-panel-sticky` (`#asset-iface-wrapper`) so rows scroll inside it and the column labels, with the sort + filter controls that live in them, stay on screen while walking a 48-port switch. Its sizer is deliberately NOT the Services tab's: `_sizeAssetIfaceTableWrapper` takes a fraction of the slide-over body's own height, because this table sits MID-tab (Storage / Sensors / LLDP / Physical Entities follow it) so `_sizeAssetSvcTableWrapper`'s distance-to-the-body's-bottom measurement would yield a different bound on every panel scroll — and measuring only the panel body works while the System tab is still `display:none`, which is the state the table is first built in (the panel opens on General, and there is no per-tab hook to re-size from). Consequences that shaped the code: every row handler is **delegated off the tbody** (a per-row listener would be dropped on the first keystroke), the pin Sets are **mutated in place** (a rebound local would leave a re-render drawing stale checkboxes), and the collapsed-parent state is **baked into the row markup** rather than applied to the DOM afterwards. Sort + filter state persists per user AND per device class under `polaris-prefs-asset-interfaces-<assetType>-<username>` (the System tab rebuilds this container on every refresh tick, so in-memory state would be wiped mid-investigation); state naming a column this device doesn't render (PoE, the VLAN pair) is dropped on restore, since a filter on an absent column would match nothing with no visible control to clear it. Plus a cumulative errors column + LLDP **Neighbor** column (rightmost; shows the first neighbor's `systemName` plus its remote `portId` as `<sysName> / <portId>` — the system name links to that asset's view modal when the neighbor matched a Polaris asset; a `+N` badge appears when the local port saw multiple neighbors and the slide-over enumerates all of them) (FortiOS-monitored phase-1 IPsec tunnels are nested under their parent interface as child rows here — orange "IPsec" badge, status pill, remote gateway in the IP column, cumulative in/out bytes; tunnels whose `parentInterface` lookup fails fall into a final "IPsec Tunnels (unbound)" group at the bottom of the same table), and a Storage table (Poll 1m checkbox, mount, used, total, %); empty-state messages render for unmonitored assets, ICMP/SSH-monitored assets, and WinRM/AD-monitored assets (the last is a placeholder until WMI Enumerate-over-WS-Management lands). The Interface column shows the operator-set **alias** as the primary label when present (FortiOS CMDB `alias` / SNMP `ifAlias`), with the real `ifName` rendered as a small subtitle and as the cell tooltip so the operator can still correlate to switch port labels. The Poll 1m checkboxes — interface, storage, and nested tunnel — write to `Asset.monitoredInterfaces` / `monitoredStorage` / `monitoredIpsecTunnels` respectively and pin the row for sub-minute polling on the response-time cadence. Each table's checkbox-column **header** carries a select-all checkbox mirroring the aggregate state (checked = all pinned, indeterminate = some; disabled without assets-write): the interfaces one acts on every **listed** row (collapsed children and nested IPsec tunnels included) and leaves rows a filter is hiding pinned as they were — un-pinning an interface the operator can't currently see would silently stop its fast-cadence polling and drop it to 24h retention; with no filter that is every row, i.e. the pre-filter behavior — writing `monitoredInterfaces` + `monitoredIpsecTunnels` together in one PUT, while the storage one writes the whole `monitoredStorage` set. The interface/storage checkbox-column header select-alls are unchanged. The **Services tab** (`_assetServicesTabHTML` / `_wireAssetServicesTab`, gated off firewall/switch/access_point AND the `other` catch-all type — none report a unit list or a host process table, frozen-header `.table-wrapper-panel-sticky` wrapper + TableSF + `applyTableLayout("asset-services-merged")`) is a **merged unit + process inventory** (the standalone Processes tab was folded into it 2026-07). It shows one row per systemd unit / Windows service (`GET /assets/:id/services`) by default; an **Include processes** checkbox in the toolbar lazily fetches `GET /assets/:id/processes` and folds the per-program process inventory into the SAME table (services first, then processes). Rows are a unified model (`combinedRows` — `kind` service|process + synthetic sort keys `sortName`/`typeLabel`/`stateSort`/`cpuPct`/`memSort` that TableSF reads by `data-sf-key`). Columns: two **per-row** pin checkboxes (no header select-alls) — **Monitor** (combined: a service row's checkbox toggles `monitoredServices` = journal tailing, a process row's toggles `monitoredProcesses` = CPU/RAM history + logs; Monitor and Logs are one column since a row is only ever one kind) and **Map** (both → `mappedProcesses` / `mappedServices`) — then Name (unit or program, clickable), Type, State (services get the colored active-state pill `_svcStatePill` — active/running green, failed red, activating amber, else grey; processes show a dash; filtered by active/inactive/failed checkboxes via `data-sf-options`), CPU % and Memory (sort-only via `data-sf-nofilter` — no filter box). The narrow pin columns use the `.svc-pin-col` class (nowrap header + tight padding). Per-model exception rows hang under each metric row with the same Type + Symbol + Transform pattern + a Model regex input + Edit / Del buttons. +Add Manufacturer at the bottom; delete via the per-row Del button (cascade-removes metric rows, overrides, widgets). The legacy read-only **Vendor Profile Status** card was removed — this editable surface now covers that ground end-to-end. A **Custom widgets** section sits below the metric table — one card per `ManufacturerCustomWidget` with view + inline-edit modes plus a `+ Add widget` button. Fields: Name, Widget type (gauge / line / table), MIB (uploaded MIBs only — std MIBs rejected at save with a clear toast since the asset-side collector needs an enumerable symbol directory), Symbol type (scalar/table — **widgets do NOT support double_scalar** because the renderer has no combiner support), Symbol (filtered picker driven by Type), Transform (unary only), Model regex (optional per-asset gate), Order, plus a per-widget-type **Display options** sub-form (gauge: min/max/unit/warning-at; line: unit; table: no options — renderer derives columns from the latest sample). Shadow stores `_mfgWidgetEditMib` / `_mfgWidgetEditType` / `_mfgWidgetEditWidgetType` keep the dependent pickers live before save. **Every chained-select handler re-renders the whole tab, so none of them may call `renderIdentificationTab()` bare** — the rebuild comes from STORED state and would discard whatever the operator has typed. Synchronous handlers go through `_mfgRerenderPreserving(el)` (snapshot the triggering row/card's live controls → re-render → write them back, keyed on the same identity the shadow stores use). The MIB pick ALSO kicks off the async `_ensureMibSymbols` fetch, whose completion re-renders again *after* that restore from a callback holding no element — so it uses `_mfgRerenderPreservingAll()` (snapshot/restore every open editor). Without it the Name came back and then vanished a few hundred ms later on every first pick of a MIB, warm-cache picks looking fine — pinned by `tests/unit/manufacturerProfileFormPreserve.test.ts`, whose async cases fail against a bare re-render. Backend: `POST/PUT/DELETE /server-settings/manufacturer-profiles/:id/widgets[/:widgetId]`. Read path on assets: `GET /assets/:id/custom-widgets` (fetched up front in the asset-modal parallel `auxResults` pass and rendered synchronously via `_customMibTabHTML`; the **Custom MIB** tab is pushed onto the tab set only when the payload has at least one widget, so it never flashes-then-vanishes for manufacturers with no custom widgets — mirrors the SD-WAN tab's prefetch-then-conditional pattern). Samples populate on the next telemetry cadence tick via `collectAndRecordCustomWidgets`.
- Server Settings → **Identification** also has a **Manufacturer Aliases** card (admin-only) — sits between OUI Overrides and the OUI Database card. Lists every alias grouped by canonical name (table columns: Alias, Canonical, Edit/Del). Add form is a two-input row: Alias (the input string to rewrite) + Canonical (the stored value) + Add button. Edit opens a small `openModal` dialog; delete uses `showConfirm`. Every save refreshes the in-memory cache and runs the existing-row backfill in the background, so the change propagates to historical Asset/MibFile rows without a restart. The card also handles the underlying problem the OUI database creates: IEEE registers vendors under their legal name (`Fortinet, Inc.`) while discovery code stamps the marketing name (`Fortinet`), and without normalization they show up as two distinct values in every manufacturer dropdown, MIB scope picker, and vendor profile match.
- Server Settings → **Maintenance** tab (formerly "Database") groups everything operational: the Capacity Advisor card on top, then the Sample Retention card, then capacity grading, in-app updates, database engine info, storage breakdown, backups, restore, and backup history. The **Capacity Advisor** card shows per-lever current vs recommended for connection-pool sizes, monitor worker counts, queue mode, and PostgreSQL tuning settings; each lever has a per-row checkbox + a single **Stage selected** button that writes the chosen env-driven values to `.env` (restart-required) and routes the QUEUE_MODE lever through the existing `POST /queue-mode` endpoint. Advisory-only rows (`PG_MAX_CONNECTIONS` and PostgreSQL settings) have no checkbox because they require a PostgreSQL restart Polaris can't trigger. Cold-start badges appear next to cadence-driven rows while the `polaris_monitor_work_duration_seconds` histogram is still filling. The **Sample Retention** card holds the 27-input grid for `Setting("sampleRetention")` — 3 streams (Response time / CPU+memory+temperature / Interfaces+storage+IPsec) × 3 tiers (Detail / Hourly avg / Daily avg) × 3 classes (Default / Switches / Access points). Defaults 7/30/365; values are days, 0 means "keep forever for that cell". Save + Restore-defaults buttons; out-of-range values (≥3651 or negative) are blocked client-side. Takes effect on the next nightly prune and on the next chart history request (5-second cache TTL on reads). A successful Save opens a "When will the database shrink?" explainer modal (`_showRetentionPruneInfoModal` in `public/js/server-settings.js`) describing the 24-hour retention-prune cadence, whole-chunk drops vs row-delete residue, and when on-disk size actually steps down. Below the advisor + retention cards, the **Database** card carries the status pill (`Healthy` / `Action recommended` / `Critical`) plus a list of capacity reasons with suggestions, then four side-by-side stat cards: App host (cpu/ram/disk + DB co-located flag), Database (current size, steady-state size, sample-table breakdown with dead-tuple % per table), Database engine + connection pool, and Monitoring workload (monitored asset count, monitored interface count, cadences, retention). The legacy `pg_tuning_needed` inline current→recommended rows have moved into the advisor card; the `pg_tuning_needed` reason itself still surfaces in the reasons list pointing at the advisor. The legacy `pgboss_recommended` / `pgboss_overdue` / `pgboss_pending` reasons and their inline "Enable on next restart" / "Cancel" buttons were absorbed into the advisor's QUEUE_MODE lever and no longer fire. When `capacity` is unavailable (e.g. statfs unsupported), the Database card degrades to a plain "Database" header with just the engine+pool sub-card so operators don't lose connection visibility. Driven by `GET /server-settings/capacity-advisor` (replaces the prior `/pg-tuning` fetch as the Maintenance tab data source — `/pg-tuning` stays as the source for the sidebar critical-alert check in `app.js`). Back-compat: `?tab=database` deep links automatically map to `?tab=maintenance`. The sidebar on every page shows a non-dismissible **red** alert when capacity severity is critical; amber / watch reasons are card-only — there's no sidebar nag for them. Below the Database / Advisor / Updates group sits the **Platform Lifecycle** card (`renderPlatformLifecycleCard` in `public/js/server-settings.js`, fed by `GET /server-settings/platform-lifecycle`): one row per stack component — Node, PostgreSQL, TimescaleDB, Go, Java, nginx, the OS, PgBouncer, Prisma — with its installed version, lifecycle track, supported-until date, status pill and Polaris's target, worst-severity first. Rows reuse `_capacitySeverityCssClass` so the colour vocabulary matches the capacity card, and a row needing attention expands a `<details>` carrying the upgrade playbook's ordered steps and the full lockstep file list. **It has no action buttons on purpose** — nothing on it is one-click fixable, unlike the two capacity reason codes that legitimately get one, and a button that cannot do the thing would be a lie. Full width of its own rather than paired with Updates: it wants six columns and pairing recreated the crush the advisor card had to solve. A dataset older than 180 days adds an amber "refresh the dataset" line (the app states the review age; refreshing it is `/polaris-tech-lifecycle`'s job), and a dataset that fails to load renders a visible "Unavailable" message rather than an empty card, because an empty card reads as "nothing wrong".
