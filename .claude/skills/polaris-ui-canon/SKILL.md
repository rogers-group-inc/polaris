# Polaris UI canon

When there are several ways to build the same thing (chart, modal, slide-over, sortable
table, wizard, row menu), this skill names the reference implementation new work must
match. **Read `design/POLARIS-UI-GUIDE.md` first** for the long-form contract (tokens,
themes, shell, tables, modals, badges, z-index, the phone SPA, the alert email), then the
canon files here for *which file in THIS repo* to copy. `public/` is the living source.

**Design systems.** `design/desktop/` and `design/mobile/` are the sources of the two
design systems published as claude.ai artifacts — Polaris UI (desktop, plus the alert email
page) and Polaris Mobile (the phone) — built with the app's own `public/css/styles.css` /
`mobile.css` as their stylesheet and published read-only (`.design-sync/NOTES.md`).
**Design first:** a NEW chart, slide-over, modal, widget or phone sheet starts as a design
canvas built on the matching system (`Artifact quickstart`, intent `design`) for the user to
review and approve before any code is written; build it to match the approved canvas, add
the pattern as a page under `design/<system>/components/` in the same branch (the build
fails on a class the app stylesheet does not define), and re-sync. A change to an EXISTING
pattern skips the canvas unless its look changes. A UI commit that touches
`public/css/styles.css` or `mobile.css` is a re-sync trigger even with no page changed.

## Frontend conventions (always apply)

Vanilla JavaScript SPA served from `/public/`. **No build step** — plain ES modules, multi-page layout with client-side navigation in `app.js`, **three SELECTABLE themes in two families** (`morning` / `noon` daylight, `nightfall` dark — the retired `dark`/`light` ids are recognized nowhere; branch on `isLightTheme()`, never on an id) plus the `afternoon` **transit palette**, a real token block with a position on the strip and no `THEMES` entry that the sidebar band travels THROUGH on noon → nightfall and never persists, per-user panel lock on every modal and slide-over. Modals, slide-overs and menus are **frosted glass** — a translucent mix of the theme's own ground under a shared `backdrop-filter`, with one mix for all three themes (nightfall matched to morning and noon 2026-10-06); the token set and the four things that silently break it are in polaris-ui-canon → canon-shared-kit.md § Floating-surface tokens. Never give a new floating surface a background of its own. A surface that merely rests ON the page takes an elevation token instead, by what it is: `--shadow-card` for a big opaque content box (every card, the dashboard widgets, the map and graph canvases, and `.chart-box` — the plot surface every SVG chart in the asset slide-over is drawn into), `--shadow-control` for small chrome, `--shadow-md` for a menu or dropdown. `--shadow-sm` is retired — it painted the cards flat on the daylight pair. Since 2026-10-04 the resting surfaces are glass too: the sidebar, every page-level card, list tables, the table tabs and bulk bar wear `--rail-glass-bg` (`--card-bg`), selected chips `--chip-glass-bg`, over a `--page-glow` painted by one fixed `html::before` layer — top centre on noon and nightfall, the bottom edge on morning — built from `@property`-registered parts that animate only during a theme change (`html[data-glow-turn]`, never on page load) and that must NOT inherit (an inheriting part restyled every element every frame; theme changes crossfade as one view transition where supported — canon-shared-kit.md, frontend-surfaces.md). Page changes are a cross-document view transition with the sidebar held still; every app page — and only app pages, so logging in never crossfades — links `page-transitions.css` (the opt-in), and needs theme-init.js in its head, the end-of-app.js cached nav render and the `rel="expect"` render-block (frontend-shell.md). A blur goes on a `::before`, never on an element that holds frosted or `position:fixed` children, and never with `saturate()` on an unfilled bar. The phone mirrors all of it in mobile.css. The rules are in canon-shared-kit.md § Floating-surface tokens and canon-mobile.md § Elevation and the page glow.

**Checking a `public/` edit: `node --check <file>`, then its unit tests — never ESLint.** `npm run lint` is `eslint src`; the config has no browser environment, so `npx eslint` on a `public/js/` file reports a wall of `no-undef` on `window` / `document` / `api` that is all noise (twice on 2026-10-28). The vm-sandbox and happy-dom tests under `tests/unit/` that load the file are the real check. Two harness traps there: Node 21+ has a read-only global `navigator` (`Object.defineProperty(globalThis, "navigator", { value, configurable: true, writable: true })`), and `(0, eval)(src)` puts the file's top-level functions on Node's global, not on the happy-dom `window`. A side-by-side theme mock never nests one theme family's panel under another's `<html data-theme>` — every `:is([data-theme=…]) .x` rule matches through any ancestor; render each family as its own document, and copy the page's font `<link>` too.

**Pages** (nav entry → page → gate). Every sidebar entry whose page can 403 carries a permission gate (`perm: [key, level]`, or `anyPerm: [[key, level], …]` for a multi-key page like IPAM) — **kept in lockstep with `pageRequiredPermission` in `src/app.ts`**, which bounces a typed URL for the same page. An ungated entry advertises a page whose first list fetch is the only thing telling the operator they can't be there.

**List-page conventions.** A list table is TableSF (per-column sort + inline filters) + `setupColumnLayout` (resizable/hideable columns) + a frozen header with the body scrolling inside `.table-wrapper-sticky` + `renderPageControls` (centered pagination, right-aligned "Show N"). Sort, filters, column widths/visibility and page size persist per user under a `PolarisPrefs` key and are **restored before the first render**, so the initial paint carries the operator's setup instead of flashing defaults. Row verbs are a **context menu on the row's name** (`showRowMenu` in `app.js`), not an Actions column — a left click on the name runs the menu's `primary` item (Open), a right click shows the menu (canon-tables-lists.md § Row context menu). **The standard row gestures, on every table whose rows can be opened or acted on (operator decision 2026-10-29): click the row selects, click the name opens, double click the row opens, right click the row selects + shows the menu** — all four from one `<tr data-row-menu-row>` marker, never a subset. On the Assets list the selection's verbs live in that menu too — the bulk bar is hidden and read as the menu's state carrier. Column widths are decided in `table-sf.js`, never in CSS — under `table-layout: fixed` the `<col>` beats a stylesheet rule and the pin loop overwrites `widths[]` anyway; a page opts a utility column out of the 34px `FIXED_COL_W` track with an inline `style="width:…"` on its `th`. The **auto-fill (last resizable) column is floored** at `max(AUTOFILL_MIN_W, its declared width)`: starved below its label's min-content it wraps one letter per line and stretches the whole `thead`, so overflow goes to the wrapper's horizontal scroll instead — and when over-committed it keeps its own saved width rather than taking the leftover, so the row scrolls instead of cutting that column off. Rows are selected by clicking them — click, drag, Shift / Ctrl+click, Ctrl+A, a click off the table clears — never by a visible checkbox: the `td.cb-col` boxes stay as the hidden state carrier, and selection rides `tr.selected` (`syncSelectedRows`; canon-tables-lists.md § Row selection). Every status pill is the pill family (canon-shared-kit.md) — never an inline fill, border or radius.

**Modal conventions.** `openModal` reuses ONE shared `#modal-overlay`. A surface that must stack *over* an open modal (the address-book picker at z-index 1300, its editor at 1320) therefore **builds its own overlay** — calling `openModal` would destroy the form DOM underneath. A standalone overlay still has to restore focus, trap Tab, and call `_ensureLockButton` itself, because that injector's MutationObserver only watches the shared overlay. Reveal through `revealOverlay` (or the same rAF-plus-`setTimeout` pair): **rAF does not fire in a hidden tab**, so a dialog opened in the background would be built and never shown. Panel-lock state lives on `window.__polarisPanelLock` and `initPanelLock({user})` is idempotent + late-safe — app.js can be evaluated twice, and a fresh file-scope object would reset the lock while the injected buttons kept claiming the old state. Wizard stepper CSS is shared in `styles.css`.

**Integration modals are one shape, not nine.** Build every "connect us to another system" dialog with `openIntegrationModal({product, action, tabs, requires, onWire, onTest, onSave})`: title `"<Action> <Product> Integration"`, General tab first then Monitoring then feature tabs, footer `Test Connection · Cancel · Create/Save Changes`, field ids unique ACROSS tabs so one pass collects the whole form. Test is gated on `requires` and the toast NAMES the missing fields; **saving is never blocked on a passing test**. The tab set and the required-field list are declared ONCE per type (`_integrationTabs` / `_INTEGRATION_REQUIRED_FIELDS` in `integrations.js`) and both the Add and Edit flows walk them — they used to be two hand-maintained arrays, so a tab added to one silently missed the other. Secrets are dropped from `requires` on the Edit flow, where a stored one renders blank.

**Charts** are hand-rolled SVG. They render labeled translucent maintenance bands over window gaps (`_maintenanceBandLayer`), dive to the baseline in red across a failed poll and in **grey** across one the upstream explains (`_CHART_DEP_COLOR`; the same value lives in `public/js/mobile/charts.js` and `src/utils/sparklineSvg.ts` — change one, change all three), and may shade the line by automation severity — the ladder comes from `GET /assets/:id/metric-thresholds` (server-side, off the engine's own `resolveTierLadder`) so shading can never disagree with what actually fires. Two chart shapes beyond the single line have their own canon sections: a **many-series** chart whose series count comes from the data (one line per CPU core — palette rules, legend toggles, and why a missing dimension gets no point rather than a zero) and a **stacked-area** chart for a reading that is a composition rather than a level (the memory bands). **No data series may be red or grey** on any of them, those being the missed-poll and dependency-down colours.
