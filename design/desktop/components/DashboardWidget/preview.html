Dashboard widget

Every widget is one article.dashboard-widget: a one-line header, then a body that scrolls. Widgets sit in columns 3, 4, 6 or 12 of a 12-column canvas and are 1×, 2× or 3× tall (280 / 576 / 872 px). Two body shapes cover the catalogue: a ranking (name, bar, value) and a list (title, sub-line, right-hand age or state, grouped by gate or site).

With no "since" to show, the right-hand slot carries the row's state as a pill. Every state is a word, never colour alone.

Rules
  • Header: the title is one ellipsized line. Count pills sit at its head, one per active-alert severity among the rendered rows. View mode shows the export (↧); edit mode shows sort, height, gear and remove, all in one 28 px box.
  • Row colour: a value bar runs accent → color-warning → color-danger on the widget's thresholds. A row whose device carries an active alert takes that severity's colour instead, so the bar can never disagree with its pill.
  • Severity pills: notice widget-pill-neutral, warning widget-pill-amber, serious widget-pill-orange, critical widget-pill-red, informational widget-pill-watch. An acknowledged row dims its own parts to 0.6 and adds an "ack <owner>" neutral pill at full strength.
  • Identifiers (IPs, ports, tunnels, mount paths) go in the muted detail beside the name, and the full name rides the cell's title.
  • Clicking a row opens the device's slide-over in place, on the tab the row is about. Ctrl, meta and middle clicks keep the link.
  • Settings live in the gear popover: widget controls first, then Minimum severity, then the Regions / FortiGates / Asset types filter fields. A change applies at once; there is no Save.
